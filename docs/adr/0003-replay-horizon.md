# 重放地平线：重放从版本标注的基线快照开始，而不是从序列 1

**Status:** accepted（方向已定，2026-09-12；**实现排在批 0 之后**）

全量重放目前在内存里同时持住整份账本（`commitFullReplay` 先
`ledger.validPrefix.map { it.event }`，而 `replay` 的两遍结构必须持有全部作答、
全部记忆与掌握度状态）。账本永不裁剪、每次安装只有一个学习者，因此它的规模随安装生命周期单调增长。
配合「不可分块」，结论是：**一份大到装不进内存的账本在现有设计下不可恢复。**

决定的方向：保留一条**按投影版本标注的基线快照**，让重放从基线开始而不是从序列 1 开始。

## 成立条件（可机械检查）

基线只有在**剩余账本里的修正不会跨过它**时才有效——
即：剩余账本中任何 `AttemptCorrection` 所指名的作答，其序列号必须**不早于**基线快照的检查点序列号。
修正追溯生效，是唯一能让「前缀」与「整体」不等价的东西；把这条检查做在选取基线时，等价性就恢复了。

这条检查不是「尽力而为」：不满足就必须回退到从序列 1 重放，而不是带着一个不等价的结果继续。

## Consequences

- 它不违反 ADR-0002：基线**本身**是一次完整重放的产物，仍然没有任何前缀被当作完整结果提交过。
- 它要放宽一个现成的约束：`LearningProjector.requireCompatibleSnapshot` 目前要求
  「投影版本变化必须从空快照重放」。放宽它需要一个新的、明确的入口，而不是把 `require` 删掉——
  否则「版本变化必须重算」这条保护会一起消失。
- 没有它，上界就是一条**用户可见的永久失效**：撞上的安装无法完成投影版本升级。
  所以上界与地平线是同一个决定的两半，只是实现顺序不同。
