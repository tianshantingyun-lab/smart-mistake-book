# 知识结构、检索与学习记忆边界

## 当前结论

知识结构和检索主链路已经可用，但当前可安装的正式内容仍只是九科基础样例，不是完整的高中知识目录。发布样例包包含九个板块、十九个细知识点和两条明确的前置关系；另有覆盖九科、125 个课程模块和 1322 个候选知识点的制作草案，但九科均未完成正式审校，不能被编译为发布包。扩大内容覆盖时必须沿用现有的来源核验、版权登记、人工审校和导入约束，不能让模型生成的候选内容直接成为事实。

学生错题、学生掌握和公共知识当前已分别由 `student-mistakes.db`、`learner-mastery.db` 与 `high-school-knowledge.db` 三个独立业务库承载，并由不同的生产 owner 打开。兼容期的 `smart-mistake-book.db` 仍承载尚未退出的会话与迁移桥接职责，但不得重新保存上述三类业务事实。三库不建立跨库外键或跨库 SQL，也不允许模型直接查询；本地编排服务只能使用稳定 ID、目录版本、固定修订和幂等凭据做有上限的批量关联。

Room v22 已加入独立的本地检索索引，v24 又为“科目 + 直接学习顺序目标”增加组合索引。前者解决旧实现“先按名称截取整科前 8192 条，再做匹配”可能漏掉后部知识点的问题，后者避免查直接学习顺序时扫描整科关系。索引只负责缩小候选范围，不替代来源核验、模型语义归类或学习情况判断。

| 检查项 | 当前状态 | 结论 |
|---|---|---|
| 知识点层级、别名、直接学习顺序 | 有数据库结构、导入约束和环检测 | 工程链路可用 |
| 版本化内容包 | 已从 Kotlin 硬编码迁移为严格 JSON 资源，支持独立增补和审查 | 工程链路可用 |
| 讲解资料与题库分权 | Room v26 独立保存概念讲解、方法模型、易错说明和例题；无作答、评分或复习身份 | 工程链路可用 |
| 完整九科知识内容及足量学习顺序 | 制作草案覆盖九科、125 个模块、1322 个候选知识点；正式审校为 0/9 科 | 尚未完成，编译器会拒绝发布草案 |
| 本地候选查找与分科隔离 | 有独立索引、候选上限和真实 Room 回归 | 工程性能通过当前门槛 |
| 真实题目检索质量 | 只有随包回归和合成压力数据，没有 2700 道人工标注真实题 | 尚不能判定过关 |
| 学习情况读取 | 单科内跨题共享、跨科隔离，已覆盖十万条学习事件压力测试 | 模拟器性能通过当前门槛，仍需 ARM 真机 |
| 错题集、掌握库与知识库物理隔离 | 三个独立数据库、独立生命周期 owner、无跨库 SQL/外键 | 工程边界已建立，仍需最终真机恢复验收 |
| 用户端语言 | 页面、无障碍和模型可见输出均设防泄漏检查 | 当前已设硬边界 |

## 三个数据库的固定边界

### 公共学科知识库

- 独立文件名为 `high-school-knowledge.db`，由经过签名和哈希核验的版本包安装；运行时业务只获得只读接口。
- 保存九科目录、稳定知识点 ID、规范名称、常用说法、章节映射、直接学习顺序、讲解方法、典型例子结构、资料出处、复用权限和检索派生索引。
- 不保存 learner ID、作答、错题收藏、掌握度、复习时间或模型对某个学生的判断。
- 模型提出的新知识只能进入包制作与复核流程，不能直接写入已安装知识库。候选通过多来源核验、独立复核、覆盖回归和签名后，才随新版本整体替换。

### 学生错题集

- 独立文件名为 `student-mistakes.db`，保存题目、题目修订、原图及文档引用、错题收藏、题目分类、知识点稳定引用、复习队列与复习会话。
- 不保存掌握概率、证据权重、模型归因候选或公共知识正文。
- 错题和复习数据只引用 `practiceUnitId`、`problemRevisionId`、`knowledgeNodeId` 与目录版本；删除收藏不会越库删除已经成立的学习事实。
- 批量导入、题目去重和图片转文档在本库内保持幂等。复习计划由服务层读取掌握摘要后写回本库，不通过跨库 JOIN 临时拼装。

### 学生掌握库

- 独立文件名为 `learner-mastery.db`，只保存不可变学习事实、来源证明、候选归因、复核、已应用回执、分科掌握投影、记忆把握度和模型可读摘要。
- 学习事件保存错题集中的稳定题目引用、稳定知识点 ID、目录版本和证据发生时的必要快照，不复制题面、图片、错题收藏或知识正文。
- 错题集删除、聊天删除和收藏状态变化不能级联删除掌握事实。三库升级或恢复后若稳定引用无法核验，相应事实进入待复核，不做猜测性重绑。
- 原始学习事实不可变；掌握投影是带策略版本的可重建派生数据。时间流逝只降低当前可回忆程度，不删除过去的正向证据或把“曾经掌握”改写为“从未掌握”。

### 服务层关联

1. 错题集先返回当前题的稳定题目引用及知识点引用，不返回整库题面。
2. 用当前题和科目在知识库召回少量候选知识点，本地归因门禁只允许模型从本次 allowlist 中引用稳定 ID。
3. 按 `learnerId + subject + knowledgeNodeId + catalogVersion` 从学生掌握库批量读取少量掌握摘要，默认不读全科历史。
4. 服务层把题目引用、知识名称和掌握摘要合并成有上限的模型上下文；任何一侧超时都失败关闭，不做跨科或模糊 ID 猜测。
5. 相关错题先在错题集按科目、知识点和时间索引筛选，再由服务层使用掌握摘要重排；任一数据库都不执行跨库 JOIN。
6. 写入时模型只能提交“观察候选 + 证据引用 + allowlist 句柄”。本地验证 capability、对话、轮次、题目、科目、模式版本和来源事实后，通过幂等 outbox/saga 把错题事实转成掌握库中的不可变来源证明；模型不能构造证明或指定权重。

这种拆分避免公共知识包升级触碰学生隐私、错题删除破坏掌握历史，也防止知识检索或错题展示为了方便而获得写入掌握库的权限。

## 内部关系

- `parent_knowledge_node_id` 表达科目内的“板块 → 知识点”归属。
- `aliases` 合并同一知识点的不同常用说法，不另造重复节点。
- `PREREQUISITE_OF` 表达有可靠资料支持的直接前置关系。
- 关系必须同科目、两端均已核验、有来源定位、没有自环和有向环。
- 检索只补充直接前置知识点，不把整条依赖链一次性塞给模型，避免上下文膨胀。
- 暂不加入“相关”“相似”等含义宽泛的边；它们容易造成误召回，也不应被用来推断学生掌握情况。

## 版本化内容包

- 随包内容位于 `core/data/src/main/resources/knowledge/`，目前使用 `schemaVersion = 1`。每个包明确记录版本、来源命名空间、审校时间、原资料地址、逐科资料指纹、板块、知识点、常用说法、内容边界、资料页码和直接学习顺序。
- 解析器拒绝未知字段、缺字段、未知枚举、重复科目、重复知识点标识、跨科引用、缺失前置目标、自环和有向环；数据库入口还会再次校验 HTTPS 来源、资料许可、SHA-256、逐节点依据、同科父级和导入数量上限。
- 同一包重复安装保持幂等；本地若已经存在同 ID 但内容不一致，安装失败关闭，不用新包静默覆盖学生已有数据。
- 内容包分为两层：第一层保存课程结构、知识点、边界和学习顺序；第二层保存可按知识点取用的概念讲解、解题方法模型、表征方法、易错说明和带完整过程的例题。第二层可以出现题面片段、推导、解答和答案；“有解答”不等于“题库”。
- Schema v2 已解除旧样例“一科只能有一个板块”的结构限制，允许每科拥有多个板块，并允许可靠的直接学习顺序跨同科板块连接。覆盖声明与节点数量分离：旧 Schema v1 永远只算 2020 历史样例；当前包必须明确声明 2025 基线，以及知识目录、教学支持各自是部分内容还是完整内容。
- 是否属于题库由用途和权限决定，而不是看正文里有没有答案。讲解资料没有 `practice_unit_id`、可作答选项、正确答案键、难度、评分、学习证据或复习排程，不能独立出现在错题录入、每日复习或能力测试中；它只能辅助讲解学生已经提供或选择的当前题。
- Room v26 使用独立的 `knowledge_teaching_material` 与知识点绑定表保存讲解资料。每份资料恰有一个主要知识点，可附少量辅助或前置知识点；未核验知识、跨科绑定、来源许可不匹配和试图加入题库字段的内容都会被拒绝。
- APK 签名保护随包资源的分发完整性；资料指纹用于追踪所依据的原文版本，两者职责不同。学生数据不进入任何知识内容包。
- 这种拆分允许后续按科目或板块小批量审校和回滚，不需要每增加一批内容就改业务代码。当前仍只有九科基础样例，结构可扩展不等于内容已经完整。

### 全高中覆盖与多方资料

- 当前发布基线以课程教材研究所已明确说明正式颁布实施的《普通高中课程标准日常修订版（2017 年版 2025 年修订）》为准；2020 修订版只作为历史兼容与差异核对资料，不能继续冒充最新覆盖基线。教育部课程方案和九科课程标准提供强制覆盖骨架、范围与规范术语；教材目录和国家智慧教育平台资料用于校对章节落点与常见表述。
- 人教社等教材出版机构资料，以及学科网、菁优网等第三方教培资料，可用于发现课程标准没有展开写明的细知识、方法模型、典型表征和常见易错边界。没有明确复制许可时只登记为 `REFERENCE_ONLY`，只保存来源元数据、定位和经过独立审校后重新撰写的归纳，不复制其题库或正文。
- 完整性按“科目 → 模块/主题 → 知识点 → 方法与边界”逐层验收，九科均需覆盖；不能用少量样例、单一教材版本或模型自行补全来宣称“全高中已完成”。`knowledge-production/knowledge-coverage-ledger-2025-v1.json` 是独立范围清单：只有当前课标正文先完成审校，逐科模块与细知识点映射才能转为 `REVIEWED`。
- 当前随包内容仍是基于 2020 修订版定位的 19 个细知识点和 2 份数学讲解资料，只验证了结构、例题边界和运行时检索链路。2025 版九科范围差异整理、全高中内容生产、逐科交叉审校和覆盖清单尚未完成，因此发布门不得标记为“全高中完成”。
- `tools/audit-knowledge-coverage-ledger.ps1` 先验证九科范围清单与当前课标来源状态；`tools/audit-knowledge-packs.ps1` 再把声明为完整的内容包与清单逐点双向比对。加 `-RequireFullCoverage` 后，当前基线缺科、独立清单未审校、少点、多点、知识目录未声明完整或教学支持未声明完整都会失败。发布门用于防止误报，不替代逐条内容审校。

研究依据也支持“按可观察的小能力建模、再用真实学习数据反复验证拆分是否合适”，而不是只按整道题记忆。Liu 与 Koedinger 的课堂闭环研究说明，知识组件模型改进需要在新数据和真实教学中验证；Shi 等人的研究则明确区分“从学生作答归因到细能力”和“根据多次证据估计掌握状态”这两个任务。参考：[Closing the Loop（JEDM）](https://jedm.educationaldatamining.org/index.php/JEDM/article/view/212/0)、[The Knowledge Component Attribution Problem（JEDM）](https://jedm.educationaldatamining.org/index.php/JEDM/article/download/755/182)。GitHub 上的 [Common Standards Project](https://github.com/commonstandardsproject/api) 证明课程标准可以作为版本化结构数据维护，但其内容与许可不直接作为本项目的中国高中知识来源。

## 知识库检索

一次错题整理只处理当前科目：

1. 导入已核验内容时，本地从规范名称、常用说法和内容边界生成有上限的中英文检索特征，并与知识点在同一事务中写入。
2. 题面在本地生成最多 128 个检索特征，Room 使用 `科目 + 检索特征` 复合主键索引查找候选，不再依赖整科名称排序和固定截断。
   长题面会优先覆盖结尾设问、开头条件和正文中的分散段落，避免大量背景材料把最后的关键知识点挤出固定上限。
3. 数据库接口把 512 设为硬上限，而不只是调用方约定；本地再用名称、常用说法和内容边界精排。
4. 只有具体知识点本身命中后，所属板块才参与加权；板块名称不能单独把整组知识点找出来。
5. 先确定小范围候选，再用 `科目 + 目标知识点` 组合索引只查询这些候选的直接学习顺序关系，并补取直接需要先会的知识点；不再读取整科关系图。
6. 最多向模型提供 64 个内部节点，并在发送前使用临时别名隐藏本地持久化标识。
7. 未核验的模型候选不会进入检索结果，也不能写入学生掌握情况。
8. v21 及更早数据库升级后，首次使用某科时会在本地检查并补建缺失索引；新导入数据不需要延迟补建。

这种设计优先保证不误召回，并让完整目录规模不再受 8192 条候选截断影响。检索索引是确定性的本地派生数据，可以重建；知识点正文、来源和关系仍是事实数据。

### 技术路线取舍

- AndroidX Room 提供 FTS4，可用于一般全文搜索；但当前中文知识点需要可控的二、三字特征、别名和资料边界加权，继续使用普通复合索引更容易解释误召回来源，也不需要自定义中文分词器。参考：[Android Room 全文检索](https://developer.android.com/training/data-storage/room/defining-data#fts)。
- 本地向量检索可作为以后语义召回的第二路候选。当前不引入 `sqlite-vec`：它仍是 pre-v1，且引入后还需要嵌入模型、向量版本迁移和额外质量评测，不能替代资料核验与模型判断。参考：[sqlite-vec](https://github.com/asg017/sqlite-vec)。
- 复合主键以 `科目 + 检索特征` 开头，符合 SQLite 对多条件查询使用复合索引的方式。所有动态值继续使用参数绑定；批量读取按 400 条切分，兼容旧 Android SQLite 的 999 参数上限。参考：[SQLite 查询规划](https://www.sqlite.org/queryplanner.html)、[SQLite 参数上限](https://www.sqlite.org/limits.html)。
- 因此当前采用“本地可解释召回 → 本地精排与直接学习顺序扩展 → 最多 64 个候选交给大模型判断”。等完整知识目录和人工标注题集就绪后，再用真实 Recall@K/Precision@K 决定是否增加向量召回，而不是预先堆叠复杂度。

## 学习记忆检索

- 学习记忆以 `learner_id + knowledge_node_id` 为核心，科目由知识点归属决定；同一科目内跨题共享，科目之间不会串用。
- 一道题可以绑定多个细知识点，作答证据按绑定分别更新，不以整道题的对错粗暴覆盖。
- 学生掌握状态由确定性的、带版本的学习投影产生，模型只能提交可复核的候选归因，不能直接改写掌握程度。
- 数据库使用 `(projection_name, learner_id, knowledge_node_id)` 复合主键，并有 `(projection_name, learner_id)` 索引，支持读取单个学生的完整学习画像。
- 讲题或复习时只使用当前题已绑定的知识点去查学习画像；没有证据的知识点保持中性，不向用户显示“完全未知”等标签。
- 投影至少区分：历史掌握概率及其保守下界、正负证据质量、独立与辅助作答、不同题族覆盖、最近独立成功/失败、冲突状态、记忆稳定度和当前可回忆概率。不得压缩成一个可被任意加减的总分。
- 选择、数值和图上目标等本地可验证行为可形成强证据；开放回答和具体卡点只能形成可修订弱证据；模糊闲聊、查看答案和“我做完了”等自报不能改变细知识掌握。
- 提示、重试、已看答案、选项猜中和重复题族必须降低或排除正向权重。证据权重由统一策略表按证据属性计算并带版本保存，禁止按题号、题面文本、测试样本或单一题型写分支。
- 多知识点题只更新被步骤或错误位置明确定位的知识点。无法定位时保留整题事实和待归因状态，不能把题目涉及的所有知识点一起降级。

### 学生掌握库的数据形态

- `source_fact` 只记录本地实际发生的行为及其不可变来源证明，不包含知识归因或模型指定的权重。
- `observation_candidate` 保存模型建议的知识点句柄、证据定位和置信声明；它必须经过 allowlist、科目、题目、轮次、目录版本和证据门槛校验，不能直接进入掌握投影。
- `observation_event` 是通过本地准入策略后形成的不可变账本事件。事件持久保存 `admissionPolicyVersion`、`ruleId`、证据等级、独立性、提示/重试/答案暴露、题族引用和知识目录版本，策略升级时可以完整重放。
- `mastery_projection` 分开保存历史掌握强度与当前可回忆程度，并保留概率下界、有效证据量、独立成功/失败时间、题族覆盖、冲突状态和投影版本；它不是事实源，可以由账本重建。
- `mastery_digest` 是面向讲题和复习的窄表，只保留当前请求真正需要的日常状态、近期可靠方向、冲突位和 `asOf`/策略版本，不保存完整时间线。
- `review_case` 保存低置信、跨版本、相互冲突或来源证明缺失的候选；在复核完成前不得修改投影。
- 错题引用使用 `practiceUnitId + problemRevisionId + mistakeStoreVersion`，知识引用使用 `knowledgeNodeId + taxonomyVersion + catalogRevision`。掌握库不对另外两个数据库建立外键，引用失配时进入复核而不是静默重绑。

权重不是让模型填写的任意小数。本地 `EvidenceAdmissionPolicy` 根据事实类型、是否本地可验证、是否独立、提示/重试/答案暴露和题族重复度选择固定的版本化规则；`MasteryProjectionPolicy` 再统一处理正负学习率、不确定度、冲突和记忆稳定度。策略只能全局升级并通过跨科留出集校准，不能按题号、题面、验收图片或单个测试调整。

### 掌握机制的研究依据与校准边界

- 经典 Bayesian Knowledge Tracing 会显式区分初始掌握、学习转移、猜对和会做却失误；本项目因此不把一次对错直接等同于“会/不会”，并把可验证性、提示、重试和答案暴露保留为可重放证据属性。[Corbett 与 Anderson 1995](https://doi.org/10.1007/BF01099821)
- Performance Factors Analysis 分开累计成功与失败，并讨论一道行为涉及多个技能的情况；本项目对应地使用步骤级知识绑定、正负证据分轨和题族去重，而不是把整题所有知识点一起升降。[Pavlik、Cen 与 Koedinger 2009](https://files.eric.ed.gov/fulltext/ED506305.pdf)
- Half-Life Regression 把长期记忆强度与经过一段时间后的可回忆概率分开；本项目也把历史掌握事实和“当前记忆把握度”分开保存，时间只影响复习优先级，不抹掉历史正向事实。[Settles 与 Meeder 2016](https://research.duolingo.com/papers/settles.acl16.pdf)
- 深度知识追踪说明学习序列可以包含复杂依赖，但它需要足够、真实且无泄漏的数据；在当前纯本地、数据尚不足的阶段，不把不可解释的神经网络输出直接当作学生事实。[Piech 等 2015](https://papers.nips.cc/paper/2015/hash/bac9162b47c56fc8a4d2a519803d51b3-Abstract.html)
- 多知识点题若把同一题的标签拆成多条相邻训练记录，可能产生标签泄漏；校准集必须按学生、题目和题族分组切分，不能让同题变体跨训练集与留出集。[KTbench 2024](https://arxiv.org/abs/2403.15304)
- 模型比较必须复用同一预处理和切分协议；错误评测会明显高估知识追踪效果。因此发布前除 Recall/Precision 外，还要报告按学生分组留出的 log loss、Brier score、校准误差、负面归因精确率，以及不同科目和证据类型的分层结果。[pyKT 2022](https://proceedings.neurips.cc/paper_files/paper/2022/hash/75ca2b23d9794f02a92449af65a57556-Abstract-Datasets_and_Benchmarks.html)

这些研究只约束模型形态和评测方法，不提供可以直接照搬的高中九科权重。当前默认参数必须保持保守、版本化和可回放；只有跨科真实留出集达到预先固定的门槛后，才能整体发布新的校准版本。

为保证快速调取，掌握库至少提供三条有界查询：按当前知识点集合批量读取、按科目读取最需要巩固的少量摘要、按科目读取最稳定的少量摘要。常用索引以 `learner + subject + knowledgeNode + policyVersion`、`learner + subject + status + lastEvidenceAt` 和 `learner + subject + lastIndependentErrorAt` 开头；模型调用不经过“先读全科再在内存截断”的路径。

### 低消耗模型摘要

- 模型不读取完整时间线。默认只提供当前科目、当前题相关的最多 12 个知识点，以及每个知识点的日常名称、简短状态、近期可靠证据方向、是否有冲突和是否应避免重复提问。
- 持久化 ID 在模型边界转换为本轮临时句柄；返回时再由本地 allowlist 解析，避免模型保存或猜测内部 ID。
- 摘要从学生掌握库的一张窄投影表一次批量读取，再从知识库一次批量补名称；禁止 N+1 查询。
- 对话模型只获得完成当前讲解所需的摘要。全科趋势、完整证据时间线和其他对话内容不进入提示词。
- 摘要以结构字段传输，不生成重复说明段落；同一题内按投影版本缓存，任何新学习事件使对应知识点缓存失效。

### 模型权限

模型侧只暴露有范围的命令，不暴露 DAO、SQL 或通用读写工具：

- 读取当前对话的必要上下文。
- 读取当前题、当前科目、allowlist 知识点的掌握摘要。
- 检索当前学生同科目的少量相关错题。
- 提交学习观察候选、知识归因、错误归因或归因修订。
- 请求保存当前真实题目。

每次调用都必须携带短期 capability，绑定 learner、conversation、turn、problem、subject、modeVersion、知识包版本和幂等键。跨范围、过期、证据引用缺失或知识点不在 allowlist 的调用直接拒绝，并写内部审计记录；拒绝原因不以技术术语打扰学生。

## 用户端词汇

内部类型名、表名、检索名和模型协议名不得出现在页面、无障碍朗读、通知或错误提示中。模型生成的待完善查询和内部父级名称同样不直接展示；学生端只按科目汇总“几类知识点分类正在整理”和涉及题数。
学生端“学习掌握”页的设备测试会检查下列内部词没有出现在可见文本中，防止以后改界面时意外泄漏。
模型生成的分类名称、摘要、复习说明、关系理由、知识点名称和步骤说明还要经过独立语言检查；命中内部工程词时整次结果失败关闭，不把原词显示给学生。

| 内部含义 | 用户端说法 |
|---|---|
| 细粒度节点 | 知识点 |
| 父级节点 | 板块 |
| 前置边 | 学习顺序 / 需要先会 |

## 性能门槛

- 测试规模：单科 12000 个知识点、11999 条前置关系；目标知识点位于第 12000 条，明确越过旧方案的 8192 截断线。
- 测试路径：真实 Android Room/SQLite 索引候选读取、定向关系读取、前置知识点补取和本地排序的完整链路。
- 完整检索连续十次的硬门槛为 p95 小于 150 ms；单个学生 12000 条掌握记录读取的硬门槛为 p95 小于 250 ms。
- 2026-07-23 API 36 x86_64 模拟器最新实测：完整检索十次为 `[21, 21, 23, 20, 21, 21, 22, 20, 22, 22] ms`，p95 为 `23 ms`。候选查找为 `18–21 ms`，直接学习顺序查询为 `0–1 ms`，补取和精排均为 `0–1 ms`。
- SQLite 执行计划确认候选查找命中 `科目 + 检索特征` 覆盖索引，直接学习顺序查找命中 v24 新增的 `科目 + 目标知识点` 组合索引；测试会在执行计划退化为扫描时失败。
- 同一设备读取单个学生的 12000 条掌握记录十次为 `[95, 67, 59, 55, 56, 54, 59, 55, 56, 52] ms`，p95 为 `95 ms`；错误的学生标识读不到其他人的记录。
- 2026-08-01 的十万条学习事件基准中，掌握摘要查询 p95 为 `8.752 ms`，当前题精确上下文查询 p95 为 `5.152 ms`，均低于计划中的 `30 ms` 门槛；该结果仍然只是 API 36 x86_64 模拟器证据。
- 扩展知识检索压力基准覆盖 5 万知识点、100 万关系和 25 万检索特征，完整候选召回 p95 仍低于 `50 ms`；这验证索引与有界查询，不代表知识内容或语义标注已经完整。
- 九科十九个内置细知识点各用一条独立表达做回归，19/19 不仅找到预期知识点，而且把它排在同粒度候选首位，候选没有跨科串入；这只证明随包样例和固定表达链路正确，不代表完整目录的统计质量。
- 这组数据是调试构建、单一模拟器上的工程基准，不等同于所有低端真机结果；发布前仍需补至少一台低端 ARM 真机和一台主流 ARM 真机。

## 仍未完成

- 可安装内容仍是结构样例；九科 125 模块、1322 个候选知识点目前只是未审校制作草案，正式审校为 0/9 科，不能作为完整知识库发布。
- 讲解资料目前只验证了方法模型和例题两种类型；九科的概念讲解、方法模型、表征方法、易错说明与例题覆盖仍未完成。
- 当前测试证明了已知相关表达能被快速找回，但还缺人工标注题集上的 `Recall@K`、`Precision@K`、漏检率和跨学科串入率评测。
- 三库已完成物理拆分、独立 owner 与稳定 ID 编排；仍需在发布用 ARM 真机完成并发升级、进程中断、单库损坏和整机恢复验收，兼容数据库也要继续证明不能重新取得三类业务表的所有权。
- 掌握投影仍需用跨科留出集校准证据权重、猜测率、提示/重试影响、题族重复衰减和记忆稳定度；任何参数不得针对验收题单独调节。
- 关系目前只接受可靠资料支持的直接“需要先会”关系；不会用宽泛的“相关”关系扩张上下文。
- 低端与主流 ARM 真机性能仍未验证，因此不能宣称所有手机都达到同样耗时。
