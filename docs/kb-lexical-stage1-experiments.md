## 2. 实验臂定义（逐臂口径写死）

**所有臂共用的口径**：

- **题面** = 冻结金标 `tools/kb_coverage/tables/golden_queries_v1.json`（90 条，10 章 × 9 条，sha256 `7c004b763bdd49556e11ff1c9500c9461b09a7383b77f230fa8fd35754e6ae39`；本会话复算复核）。
- **分词** = 生产提取器，**不许另写一份**：索引侧 `KnowledgeSearchFeatureExtractor.fromNode`，查询侧 `KnowledgeSearchFeatureExtractor.fromQuestion`（`core/database/src/main/kotlin/.../KnowledgeSearchFeatureExtractor.kt:30,44`）。
- **命中定义** = 返回的前 5 名里存在 `knowledgeNodeId` 以 `:atomic:<expectedSlug>` 结尾的节点（`core/data/src/test/kotlin/.../RetrievalBenchmark.kt:213-229`，`SCORED_TOP_K=5`）。
- **指标** = 主集 Recall@5（命中/90）、逐章 Recall@5（章内命中/9）、MRR（命中名次的倒数均值）、逐题 MISS 清单；每臂每指标都落盘。
- **候选过滤** = 按科隔离 + `verification_status ∈ {CURATED, SOURCE_GROUNDED, USER_CONFIRMED}`（与生产 B 路一致，`RetrievalBenchmark.kt:259-263`）。

| 臂 | 定义（口径写死） | 参评 |
|---|---|---|
| **A** | **FTS5 + `bm25()`**：索引内容 = `fromNode` 特征串**空格分隔**（逐节点一篇文档）；查询 = `fromQuestion` 特征**以 OR 连接**成 `MATCH` 表达式；`ORDER BY bm25(<表>) ASC`（FTS5 的 `bm25()` 返回负值，**升序即最优**）；取前 5 判分 | ✅ 生产候选 |

## 3. 不许在判官上调参（固定参数纪律）

1. **判读配置 = 固定权威参数**：FTS5 `bm25()` 的 `k1=1.2` / `b=0.75` 是 SQLite 官方的**硬编码**（外部取证见 §5），**不可调**。臂 A/A'/B/C/D 的判读数全部取自这套参数。
2. **参数扫描只作诊断**：任何 k1/b 变体、top-k 变体、门控宽度变体、boost 变体，只能出现在"扫描诊断"段，**必须显式标注"非判读数"**，不得进入 §1 判读、不得写进 `chosenArm`。
3. **禁止事后改动**：判读线（§1）、命中定义与判分口径（§2 共用口径）、金标集（§4）在出数前后**一字不动**。提升指标只能改检索器/索引/内容——"改题面让它命中"= 判定作废。
4. **镜像保真先行**：JVM 镜像与真 SQL 的差值 >5 个百分点时，先修镜像保真度、重出数，再判读（差值本身是评测缺陷，不是成绩）。

## 4. 冻结声明（金标集与判分口径）

1. **金标集不增、不减、不改**：`tools/kb_coverage/tables/golden_queries_v1.json`（90 条）+ 同名 `.sha256` 封存；两份测试各自在运行时复核 sha256（JVM 对仓库份、仪表化对 assets 副本），题面被改过就红、不进判读。
2. **判分口径冻结**：§2 的命中定义、top-5、按科隔离、可信状态过滤、主集/逐章/MRR 定义（10 章 × 9 条）——与既有金标测量台（`GoldenRetrievalJvmTest` / `GoldenRetrievalInstrumentedTest` / `RetrievalBenchmark`）同一套，本轮不另立口径。
3. **生产形状不动**：本实验只在测试侧出数；**生产检索代码在过线之前不改**（生产实现属条件性阶段，仅过线才做）。生产现状 = v1 截断索引 × 裸 B 路 limit=5（零回归形状）。
4. **不重开已锁结论**：去截断 / 宽召回统一路由已实测净伤害并回滚（KD-24，`docs/known-defects.md`），重开条件见该条目；本轮实验不构成对其的重开。

### 7.2 判分口径（**必读**：判读数与生产口径不是同一口径）

- 臂 A（以及 A' / B / C / D / T）的 0.6556 / 0.2222 / 0.5569 出自 **matched-only 口径**：只对排序后的 matched 节点取前 5，**无父节点前置**。这是实验台的诊断口径，**不是生产判分口径**。
- **生产判分口径** = store 的 `(parents + matched)` 返回形态取前 5（`core/database/.../RoomKnowledgeBaseStore.kt:125-133`，`GoldenRetrievalInstrumentedTest` 的判分方式）。在该口径下（`build/stage1-experiments.md` §10 与 §9 的 `scan-A-parentprefix` 行）：
  - **臂 A（FTS5+bm25 排序 × 生产形）= 0.5333（48/90）/ 逐章最小 0.1111 / MRR 0.1552**；
  - **基线 v1 排序 × 生产形 = 0.5444（49/90）/ 逐章最小 0.2222 / MRR 0.1511**（预注册基线，真 SQL 与 JVM 镜像零漂移）。
- **结论（本轮的正式读法）**：**在生产口径下 FTS5+bm25 排序未带来 Recall 增益（0.5333 < 0.5444），增益只在改变返回形态（matched 优先）后才出现（0.6556）**——表观的 +0.1112 来自返回形态（父节点占席被消除），不是排序增益；同样一条 FTS5 排序，只换返回形态：生产形 0.5333 → matched 优先 0.6556（+0.1222）。
- **是否改返回形态列为待用户裁定项（D1）**：`(parents + matched)` 是 KNOWLEDGE_READ / MASTERY_READ 聚焦解析的既有语义（父 topic 占席，供上层解释），改形态要逐一复核消费者（`RoomTutorToolRunner`、`RoomTutorKnowledgeContextLoader`、`RoomMistakeOrganizationRepository`）——不在本轮实验范围内，本轮不擅自改。
- 因此本文件与任何引用本轮的记录中，**不得出现未限定口径的"FTS5 严格更优"或"+11.1pp"之类表述**：正确表述是"matched-only 口径下 0.6556 vs 生产口径基线 0.5444；生产口径下 0.5333 vs 0.5444"。
- **【追加指针，2026-09-24；本节其余字面为历史记录，不改】** 生产形态已于 Stage-2（计划日 2026-09-23，代码注释的落地日 2026-09-24）**改为 matched 优先**（`RoomKnowledgeBaseStore.kt:131` = `return (matched + parents)`）：matched-only 口径与生产判分口径**自此同窗口**，真 SQL 新基线 **0.6444（58/90）/ MRR 0.5637 / 逐章最小 0.2222**（旧生产形 0.5444 / 0.1511 留档）。上表各臂的判分数（如臂 A 0.6556）在新形态下**就是**其生产口径分；判读线、`chosenArm` 与本轮结论一字未动。见 `docs/kb-stage2-report-2026-09-23.md`。
