# 智能体重构：决策台账（2026-09-23 起）

> 起因：产品需求被重述——**软件的核心是错题本（学习）垂直领域的智能体**；除设置外整个软件是它的
> 活动空间（部分设置区也是）；后端三个库（知识库 / 学生掌握情况库 / 错题库）由它灵活调用；
> **复习建立在智能体之上，本质是与智能体的交互，与讲题、聊天无区别**。因此四栏页面设计不合理。
>
> 本台账记录逐条裁定与它们的后果；细节设计另见规格文档（待写）。
> 事实基线见 `docs/architecture-research-2026-09-22.md`。

## D1 · 掌握库的写入权威 = 双轨（数值归投影，wiki 活动归知识层）

**状态**：已裁定（2026-09-23，用户选 (c)）

**决定**：智能体**不写掌握度数值**。数值永远由本地确定性投影算出。智能体的"像 wiki 一样不断
改写"发挥在**知识层**：它可以提议新增/细化/合并知识点、补充某点的边界、记下这个学生的典型误区、
标注哪种讲法对该学生有效。

**理由**：一旦模型能写分数，(1) 排程会被不可回归的输入污染，(2) 失败是静默的——不会报错，只会
让复习计划慢慢变得不合理，(3) 此前围绕"掌握度只来自合格作答事实"建立的全部论证、立项与测试失效。
而"库在长"的产品感受由知识层提供即可，那里本来就更需要被持续维护。

**好消息：这条通道已经存在，且有测试守门。** 智能体在错题整理时**已经**在产生知识层候选：

- `KnowledgeNodeVerificationStatus` 四档：`CURATED` / `SOURCE_GROUNDED` / `USER_CONFIRMED` /
  `MODEL_CANDIDATE`（`core/model/.../ProblemCatalog.kt:128-144`，`USER_CONFIRMED` 的 KDoc 明确
  写它"是该学生的最强权威"）。
- 包内容不得携带 `MODEL_CANDIDATE` 节点（`core/database/.../KnowledgeBaseImportContract.kt:164`）。
- 掌握总览只准入 `CURATED` / `SOURCE_GROUNDED` / `USER_CONFIRMED`
  （`core/database/.../dao/MasteryOverviewDao.kt:165`）。
- 内容更新**只升不降**：库里已 `USER_CONFIRMED` 的节点不被包里的值改回
  （`core/database/.../RoomKnowledgeContentReconciler.kt:27,186-187`）。

所以 D1 在实现侧的动作不是"新建一套 wiki"，而是**把这条已有的候选通道提升为智能体的一等工具**
（任何轮次都可提议，不再只在整理时顺带产生）。

**继承的不变量（不可破）**：模型生成/候选的知识**未经确认不得进入检索与教学注入**——
`KnowledgeContextRetriever` 已按准入白名单排除 `MODEL_CANDIDATE`（只放 CURATED / SOURCE_GROUNDED /
USER_CONFIRMED）。破了这一条就产生**回声室**：模型写过的东西下一轮以"可信材料"身份再喂回模型。

**D1 的唯一真正新增物**：**每学生私有的知识注释层**（当前只有"全局节点 + 学生确认状态"，没有
"这个学生在这点上的画像"这类对象；有效讲法/典型误区目前散落在会话摘要与 `tutor_message` 原文里，
跨会话无法结构化复用）。

- 必须指认它消灭的具体失败：**智能体对某个学生的有效讲法与其典型误区散落在会话里、跨会话无法复用，
  导致每次换方法/换会话都要重新摸索同一个卡点。**
- 若指认不出（例如认为会话摘要已足够），按仓库纪律 §12.2 应删掉这个新增，而不是"为了完备"加一层。

**由 D1 直接推出的非目标**：学习科学内核（`LearningProjector` / FSRS / 投影 / 排程）**不作为本次
重构对象**——它们是 D1 保留的数值权威。这与用户"内核需要大重构的地方不太多"的判断一致。

**关联证据**：`docs/architecture-research-2026-09-22.md` §2 裂缝 2（两套复习世界观）、§4.5（KB 覆盖）、
§7b（LLM-Wiki 范式与 Generative UI 改判）。

## D-Q1F · 结构原则：多入口 + 会话按现场隔离（**选 1**，不选统一入口）

**状态**：**已裁定**（2026-09-24，用户确认"好，那么就选择一"）

**决定**：采用**方案 1**——专门的任务在专门的地方做；不同地方的**会话记录互不相串**；
一条会话**只在它所属的那个地方可见**。不采用"一个统一入口"。

**用户给出的定义（逐字保留，避免我再次自造理解）**：
> 1、把不同的功能入口分开，不同功能中的会话记录不相串，只能在当前功能页面查看。
> 2、统一入口。
> 选择一台（1）是为了专门的任务，专门的地方做。而选择奥（2）就是为了一个统一的入口。

**理由（外部证据，等级见研究报告 §7d）**：
- **独立聊天入口的采用率极低**：Khan Academy 第一方数据 ~15% 持续使用其附属聊天机器人，复盘后改为
  **嵌进练习流程**；Dartmouth/Phosphor 2026 课堂部署里，RAG 聊天侧栏**整个学期 143 名学生只产生
  72 次查询、仅 14 人用过一次以上**，而**嵌进阅读工作流的**功能效果显著（通过三轮复习者期末 +7.1 分，
  d=0.66）。〔两条来源规范 URL 未取到，待核〕
- **长上下文会自我污染**：Chroma《Context Rot》（18 模型、约 194,480 次调用）证明准确率随输入长度
  单调下降（任务难度固定、且远未触达窗口），**"开新会话"被列为最有效的缓解手段**。
  <https://research.trychroma.com/context-rot>
- **连头部产品都要给统一聊天补边界**：ChatGPT Projects（2024-12-13）动因逐条是"没有任何组织手段、
  左栏堆满、上下文散落、重复上传"，并**提供 project-only memory 来划不同工作区之间的边界**。〔待核〕

**明确撤回**：我此前多说的"讲题 tab 消失"**作废**——那既不是方案 1 也不是方案 2，是我自己加戏。

**本轮定的是结构原则，不是排版**：用户已说过"四栏设计不合理"，**改的是有哪些地方、怎么划分**；
**"分开 + 隔离"这条原则选 1**。具体有哪几栏仍属"排版与编排"，按 D3 的推迟项单独商榷。

**由本决定推出、需要打破的现行规则（用户已授权不受现行文档约束）**：
1. **ADR 0001 的 UI 收敛部分作废，内核部分一条不动**。它修的"每入口各有工具面/各有门"对症；
   但顺手把六个入口收敛成一个页面这一步撤销——页面数量由**地方的数量**决定。
2. **会话的键从"入口形态"换成"现场"**：不再按 text-only / captured / saved-mistake 分三形态，
   而是"一条会话属于一个地方"。
3. 披露、工具面、写门、单一代号通道、证据锚底线、掌握度不可直写——**全部保留**（它们是内核不是 UI）。
4. "用户每次进入只表达一个意图"改写为"**学生进入的是一个地方，意图由地方承载**"。

**与 D3 的关系**：D3 判定的"智能体不是一个地点、是一层能力"继续成立；但 D3 里那个"**一个主场**"
按本决定降级为**收件箱**（历史、待确认提案、后台备料产出），**不是求助入口**。

## D-Q1G · 错题拆分到原子知识点：时机、可变性、以及换版后历史怎么办

**状态**：**已裁定**（2026-09-24，用户："这个默认成立，其他的我都同意了"，并点名
**「权威绑定在学生确认时成立」**作为默认成立的条款）

**决定（三条）**：
1. **拆分不作为入库的前置**。入库时可先挂 `pseudo:<SUBJECT>`（"未归类知识点"占位已存在），拆分
   交给**后台备料**（D2）产出候选。**权威绑定在学生确认时成立。**
2. **智能体可以随时提出重拆**，但产出永远是**候选修订**，不能直接改权威绑定（D1 的继承不变量：
   候选未经确认不进检索与教学）。
3. **绑定换版时，受影响的掌握度按新绑定重放**（复用已有的 `LearningProjector.replay`），
   而不是"只影响以后"。

**理由**：
- 第 3 条是 D1 的必要条件：D1 的核心动机是"数值可回归、可解释"；若绑定能在事实之后改变而历史
  不重算，"从事实重算掌握度"会得到不同结果——投影就不叫投影了。
- 这条路已有两个现成部件：`LearningProjector.replay`（重放通道）+
  `KnowledgeNodeSuccessors` 与 392 条退役/合并台账（节点被合并或删除时历史证据如何跟随）。
  缺的只是"题目绑定换版"这一档。
- "入库时必拆一次"是用户自己冻结的"板块和知识点允许稍后整理"原则的多余强制；交给后台备料恰好
  符合 D2 的准入判据（产出能由已有事实重算）。

**两条必须满足的要求（代价已具名）**：
1. **需要一条"`pseudo` → 真实节点"的证据转移路径**（否则掌握会先落在 pseudo 上，换了真节点后不跟随）。
2. **重拆需要冷却与配额**（类比 `MasteryWriteGate` 的 12h 冷却 + 双配额）。消灭的失败：
   **掌握度在没有新学习行为的情况下跳动，学生会失去对整个系统的信任。**

**一处歧义的显式消解（我选择并写下，若不对请推翻）**：
"权威绑定在学生确认时成立"**不等于**要新增一个逐项确认页——用户已冻结"不出现逐项确认页、归类不阻塞
保存"。消解方式是：**"保存"这个动作本身就是确认**（首次归类随保存一起成为权威、且始终可改）；
只有**改动已经成立的权威绑定**（重拆/换版）才需要学生明确点头。两条原则因此同时成立且零额外摩擦。

**Q1 至此闭合。** 已裁定：D1（掌握库写入权威 = 双轨）、D2（自主边界 = 会话内 + 后台备料）、
D3（形态 = 一层能力，主场降级为收件箱）、D4（多会话 + 默认新会话）、D5（工作区 = 会话分组）、
D-Q1F（结构原则 = 多入口 + 会话按现场隔离）、D-Q1G（拆分时机与换版重放）。

## D-Q1H · 会话隔离的键是「工作区」，不是「对象」（用户纠正）

**状态**：**已裁定**（2026-09-24，用户口述需求）

**用户原话要点**：
> 在不同工作区（比如说复习，通用智能体，后续还会新增板块）有不同的会话区域，不同区域的会话记录
> 互不相通，只能在那个区域里面查看。在每一个工作区里面的智能体的交互形式会有略微不同。
> 每一次进入，默认开一个新的对话。**不要把整个对话和题目或者错题，或者知识点绑起来。**
> 现在我们最应该讨论的是如何设置功能布局，由表及里。

**三条纠正（我的 Section 1 提案据此作废）**：

1. **工作区的定义升级**：D5 把工作区记成"会话分组的组织单位"；正确含义是**区域/板块**——
   它是**会话隔离的键**。会话记录按工作区隔离、只能在所属工作区查看。**"通用智能体"本身就是一个
   工作区**，且工作区集合是开放的（后续新增板块）。
2. **会话不绑对象**：**作废我在"设计·第 1 节"提的「一条会话最多属于一个对象」**。
   题目 / 错题 / 知识点**不是会话的归属**，只是**本轮附件**（这恰好与 ADR 0001 的 P2
   「会话不再绑题、每轮语义绑定」一致，也和 F1 修复"写工具准入回退到本轮请求侧已知题锚"一致）。
   推论：一条会话可以在其所在工作区内换题；"没带对象随便问一句"是正常形态，不需要特殊档。
3. **每个工作区里智能体的交互形式略有不同**（不是同一套 UI 平铺）。

**由此明确的工作顺序**：先定**功能布局**（有哪些工作区、边界在哪、每个区域里有什么），
**由表及里**；对象模型、会话存储、内核改造都是"里"，等表定了再往里走。

## D-Q1I · 功能布局（用户口述需求，2026-09-24）

**状态**：**已裁定**

**用户的规则（取代我提的三条判据——用户明确"我只说我的需求"）**：
> **不同的功能放在不同的独立会话区，单开一栏。**

**三条具体裁定**：

1. **错题本区不带智能体**：它是**静态查看**。没有会话区。
2. **录入（拍照 / 批量导入）单开一栏，且在错题本之外执行**——"不要和看错题混在一起"。
   执行时有**可视化进程**；**切换会话/离开后任务不能暂停**（任务不随导航取消）。
3. **学习档案区不带智能体**：**只读、可视化展示**，学生**不需要**（也不被允许）直接修改。
   需要修改时**通过通用智能体提出**，而**通用智能体不一定接纳**。

**由此得到三类区域（这是本次重构的表层结构）**：

| 类型 | 特征 | 第一版成员 |
|---|---|---|
| **会话区** | 有智能体、有**独立会话记录**，记录不出区 | 复习、通用智能体 |
| **任务区** | 有可见进度、任务跨导航持续；不是聊天 | 录入（拍照 / 批量导入） |
| **静态查看区** | 无智能体、无会话 | 错题本、学习档案 |

设置仍是配置，不属于学习活动。

**作废的提案**：我上一轮"学习档案是可编辑的共享状态"作废——改为**看在学习档案、改经通用智能体**。

**我标记的一处冲突（必须解决，否则 D1 的不变量破了）**：
D1 的继承不变量是「**候选知识未经确认不得进入检索与教学注入**」（否则产生回声室）。
但在"学生不能直接改档案 + 学生请求可能被智能体拒绝"之下，**确认门没有了学生侧**。
需要在下面三个里选一个（本轮提问中）：
- (a) 学生**主动请求**且被接纳 = 确认；
- (b) 智能体写入的知识**永久停留在候选层**，只影响该学生自己的视图，**永不进入共享检索**（= 私人注记，不是知识）；
- (c) 智能体主动提议时，在通用智能体里出现一个**明确的采纳/不采纳动作**（即 D2 的待确认区，本来就要做）。

## D-Q1J · 分区按「功能」；栏内多入口；成分不互斥（用户纠正）

**状态**：**已裁定**（2026-09-24，用户口述纠正）

**四条纠正**：

1. **录入属于"错题本栏"，但不在错题本里**：**录入与错题本分开两个入口，共享同一栏**。
   ⇒ 由此确立：**"栏"是分区单位，栏内可以有多个入口**；我之前把"功能"和"入口"当成一回事，错了。
2. **分区按功能来分**：例如 **智能体一栏、错题本一栏、复习一栏**。我上一轮给的
   "会话区 / 任务区 / 静态查看区"三分法**作为分区方式作废**。
3. **会话区与任务区不是绝对分开的**——"会话里面未必就不能看任务导航"。
   ⇒ 三类成分**不是互斥的类型标注**，而是**栏内可以同时存在的成分**。
4. **"候选知识未经确认不得进入检索"是知识库制作期的规则，不是运行时学生确认流程。**
   ⇒ 我把离线生产侧的规则误用到了运行时交互上，**方向错了**；据此我提的"确认门没有学生侧"这个问题
   **作废**。运行时的正确机制是用户给的这条：**学生的请求未必都合理，需要给智能体设置规则来判断**。

**修正后的表层结构**：

```text
栏（按功能分区）
└── 入口（同一栏可有多个入口）
    └── 成分（会话区 / 任务进度 / 静态视图，可在同一栏共存，不互斥）
```

| 栏 | 入口 | 栏内成分 |
|---|---|---|
| **智能体** | 会话（每次进入默认新开） | 会话区；**同时可看任务导航**（在跑的任务、待确认、后台产出） |
| **复习** | 今日队列 / 作答 / 复习中的会话 | 任务流 + 会话区 |
| **错题本** | ① 错题本（**静态查看**）② **录入**（拍照 / 批量导入） | 静态视图 + 任务区（可视化进度、**跨导航不暂停**） |
| **学习档案**（是否独立成栏待定） | 只读可视化 | 静态视图，**无智能体** |
| **设置** | — | 配置 |

**一条设计注记（非提问）**：学生的纠正请求被智能体按规则拒绝时，应**留痕并给出理由**；
否则"你可以跟它说、它不一定接纳"会退化成"说了也不听"，学习档案会失去可信度。

## D-Q1K · 运行中的大任务 = 全局悬浮球；栏内成分推迟

**状态**：**已裁定**（2026-09-24，用户口述）

1. **正在跑的任务全局可见**，形态是**一个可移动、可展开的悬浮小球**。
   用户明确"这样的任务不多，应该只有错题本的录入这样的大任务"——所以它**按需出现**，不是常驻装饰。
2. **栏内成分先不定**，单独讨论（会话区 / 任务进度 / 静态视图的共存方式推迟）。
3. **栏目种类和入口要继续打磨**（用户指出的下一步）。

**顺带确立一条边界（我在本轮提出、与既有裁定一致）**：
**「栏」的数量不等于底栏格数。** 怎么呈现（底栏、侧边、抽屉、手势……）属于**排版与编排**，
按 D3 的推迟项单独商榷。因此可以放心**按功能分栏**，不必为"手机底栏放不下"而合并功能。

### 附件分类规则（将成为系统提示词的硬规则 + 本地 allowlist 校验）

**内联卡**（它这轮输出的一部分，随消息出现，本地渲染；类型进 allowlist，未知类型降级纯文本）：
1. **讲解结构卡**：步骤流 / 对照表 / 公式推导链（即 `TutorGuiSpec` 的既有场景）。
2. **选择卡**：需要点选时（选择项对应真实解题分支）。
3. **结果/提案卡**：它算出来的东西——今日计划卡、合并建议卡、归类建议卡。
4. **依据卡**：它引用知识库或掌握数据时附的证据卡（下钻入口）。

**引用**（可点的链接，点开跳到该对象所在的地方）：
- 只有**对象**（题、知识点、任务、档案条目）给引用；**对象的数据点**（"上周错 3 次"）只给文字，不给链接。

**不产生任何附件的场景**（防止模型滥用）：
- 纯文本讲解/解释；数据摘要（"昨天完成 7 题"）；寒暄与情绪回应 → 一律纯文字。

**禁止的场景**：
- 把整页/整列表塞进会话（"我把错题本全列出来"）→ 只允许 ≤N 条摘要卡或给引用。
- 未被打扰时主动插播卡片 → 待确认项走角标/收件箱，不进会话插播。

### 收件箱的重新定义（回答"是什么、有没有必要"）

**D2 是什么（人话）**：学生没打开 App 时，智能体可以做"备料"——把归类建议算好、把重复题比对好、
把要拆的知识点候选列好、把明天的复习计划先摆好。**但只许做"产出能由已有事实重算"的活**，不许写
不可逆事实（作答、掌握度、正式归档、正式题面修订），不许主动推送，后台花费有独立且可见的额度。
"可重建"这条判据的理由：能重算 → 做错了重算即可；不能重算 → 它就是在写新事实，那只能发生在
有人的会话里（学生要能看见、能追溯）。

**"收件箱"要收的东西**（我上一轮没说清，这里拆开）：
1. **它主动提的、等学生点头的**（待确认项）；
2. **后台备料的产出**（它整理完、等学生看的）；
3. **"它最近做了什么"的痕迹**（审计感）。

**两个落法，请选**：
- **(a) 独立收件箱层**（在智能体栏里，默认收起、有东西时小红点）—— 三个都收。
- **(b) 最小形态（我的新推荐）**：后台只做"**有家可归**"的活——归类建议落在错题本栏、复习计划
  解释落在复习栏，各栏只挂**自己的角标**；智能体栏保留的只是**会话历史 + 一条"它最近做了什么"
  的可问条目**（学生问，它用引用列表答）。知识缺口扫描这类"没有家"的活**先不做**（YAGNI）。

**推荐 (b)**：它消灭的失败与 (a) 相同（后台产出无处落、学生不知道它做了什么），但少一个
新实体、少一处"它到底算哪栏"的争论。角标随栏走，正好符合 D-Q1I"每个地方自己的会话区"。

## D2 · 自主边界 = 会话内自主 + 后台"备料"（后台不写不可逆事实）

**状态**：已裁定（2026-09-23，用户选 (b)）

**决定**：没人使用 App 时，智能体**只做可重建、可丢弃的活**——整理归类、扫描知识缺口、预生成候选、
把明天的计划与解释先摆好。产出全部落在**待学生确认**的位置。它**不写不可逆事实**（作答、掌握度、
正式归档、正式题面修订），**不主动发起对话或推送**（至多一条"我整理好了"的完成通知），并且后台
花费有**独立且可见的额度**。

### 后台准入判据（由本决定直接推出，可机械判定）

> **一项工作只有在"它的产出能由已有事实重算"时，才允许在后台做。**

重算得到同样结果 → 可丢弃，后台做只是省时间；不能重算 → 它就是事实，只能在会话内产生。
这条判据同时排除了"后台顺手把归类写死""后台自己决定复习计划"这类越界。

### 保留下来的既有机制（因为"由人发起的会话"这个前提仍然成立）

`ModelTaskRemoteDispatchPolicy` 的 6 次派遣、15 分钟时效、进程内租约、"进程重建后必须有一次明确
继续"——这些机制的前提是"存在一次由人发起的会话"。D2 保留该前提，故这套机制**不作废、不重写**。
这也回答了上一轮 (c) 的风险：完整自主会让它们全部失效，且 BYOK 花的是学生的钱。

### 本决定的两个新增物（各自必须指认消灭的失败）

1. **待确认区**：后台产出无处落地的唯一出路是"丢弃"或"擅自写入"，二者都错。
   消灭的失败：**智能体在后台做了有用的事，却只有在学生恰好打开某道题时才能看见**（当前
   `MistakeOrganizationSection` 的整理结果就是这种"必须走到那屏才看得见"的形态）。
   在"智能体即应用"下它长成智能体主场里的一个块，**不是新加一个栏目**。
2. **后台额度**：消灭的失败：**无人监督的 BYOK 花费**。必须与前台额度分账、有上限、可见。

### 复用的既有基础设施

- `WorkManager` 已在跑批量导入驱动（`app/.../BatchImportDriver.kt:43`）与孤儿资源回收
  （`app/.../OrphanAssetGc.kt`）——但这两者都是**本地、不花额度**的类别；后台调模型是**新类别**，
  需要新的配额与可见性，不能沿用它们的默认策略。
- `ModelTaskStatus.WAITING_FOR_MODEL`（`core/model/.../ModelTasks.kt:30`）已是持久态、可恢复——
  正是"后台备料被中断后继续"的现成载体。

### 与 D1 的咬合

D1 把"模型候选知识 → 学生确认"提升为智能体的一等工具；D2 让后台最适合干的活正好是**扫描知识缺口
与提议节点**。两条决定互相支撑：后台产出 = `MODEL_CANDIDATE` 候选 + 待确认区的确认动作 →
`USER_CONFIRMED`。确认之前不进入检索与教学注入（D1 的继承不变量）。

**顺带澄清一个不需要新增对象的东西**：后台"把明天的计划先摆好"**不产生新对象**——计划本身就是
可重算投影。后台能预生成的是它的**人话解释**（"为什么是这些题"），而那正是当前算了却从不显示的东西
（见研究报告 §4.4：`ReviewReason` 内核算好、UI 零消费）。

## D4 · 会话模型：多会话 + 每次进入默认新会话 + 工作区

### 事实三：关键澄清——"从对象上召唤" ≠ "专用入口"

- **专用入口**：有自己的页面 / 策略 / 会话身份 / 工具面 = 场景矩阵（ADR 0001 已否决）。

⇒ **D3（一层能力 + 一个主场）由 (Y) 实现，不需要 (X)。** 两轮前那个看似对立的二选一，

### 事实四：插件这条线在工业界是两层，而且我们已经有第一层

| 层 | 是什么 | 代表 | 我们的现状 |

## D7 · (Y) 的界面逻辑：三条硬约束 + 一条由此推出的不变量

**状态**：(Y) 已裁定（2026-09-23）；界面逻辑的**具体方案未定**（本轮给方案中）

用户对 (Y) 的界面逻辑提出三条硬约束（2026-09-23 原话要点）：

1. **绝对不能是"点加号 → 弹出某某模式 → 点击进入模式"**这种形态。
2. **便于学生使用、理解；在功能整合中不让功能串位。**
3. **不同模式功能可能需要差异化的独立组件（或页面）来彰显不同。**
4. 附带指令：**不要回避内核重构，当务之急是把产品改好。**

### 由三条约束推出的不变量（这是界面逻辑的设计脊柱）

> **一个功能的边界，必须由「对象 × 能力」这对显式事实钉住，而不是由"学生点了哪个入口"决定。**

理由：**串位的根因就是边界由入口决定**。本仓库已有现成反例——大厅允许附图，但大厅不在采集语义链上，
于是"聊天里的图绕开披露清单出网"成了必须专门消灭的失败（研究报告 §4.5、代理报告 OVERLAP-B：契约级冲突）。
入口决定边界 ⇒ 同一个能力在不同入口下语义漂移 ⇒ 串位。对象决定边界 ⇒ 能力只在其对象上存在 ⇒ 不串位。

因此"差异化组件"的正确落点不是"给每个功能一个入口/页面"，而是**给每种「对象 × 能力」一种组件**。
用户第 3 条约束由此满足，且不必违反第 1 条。

### 内核含义（对应用户"不要回避内核重构"）

(Y) 落到内核上至少有三件事，都属真重构而非局部：

1. **会话事实模型收敛**：7 张 `tutor_*` 表 + 2 repository + 2 ViewModel + 双份文本 → 一个会话流 + 轮次附件。
2. **工具面泛化**：`TUTOR_TOOL_DECLARATIONS`（5 个）从"讲题的工具"泛化为"整个应用的能力面"，
   每个能力带自己的 schema 与门（写工具、图片资产仍走真门，见 §Q6 的取向）。
3. **提案的生命周期**（若采纳含提案的界面逻辑）：提出 / 接受 / 拒绝 / 过期——这是 (Y) 之后
   **第一个真正新增的对象**，必须能指认它消灭的具体失败，否则按纪律 §12.2 应删。
