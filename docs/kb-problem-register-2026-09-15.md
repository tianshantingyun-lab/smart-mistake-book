## A. 内容层（质量门红项 · 21 条）

**统一的根因**：A-01～A-14 中多数不是"内容写错"，而是**定稿动作未完成**——两张权威表不存在（A-16）。

### A-01 · 998 个知识点没有任何教学材料 【P0 · 决定 D-2 直指本条】
- **症状**：2573 个原子知识点中 **998 个（38.8%）零材料**。分科：数学 80/406（19.7%）、生物 99/338（29.3%）、物理 312/732（42.6%）、化学 507/1097（46.2%）。
- **失败路径**：学生在这些节点上没有可讲的依据。讲题链路走到该节点时，`referencesFor` 返回空 → 模型只能凭自身知识作答，知识库在这一格上等于不存在。
- **证据**：`[本轮实测]` 解析 `core/data/src/main/resources/knowledge/` 全部 6 个 sidecar 得到（脚本见研究文档附录 A）。
- **归属**：**D-2 的施工对象**。

### A-02 · 892 条教学材料没有任何绑定，导入时被静默丢弃 【P0】
- **症状**：10356 条材料中 892 条 `bindings` 为空。
- **失败路径**：`BundledKnowledgePackResources.kt` 在合并侧车时过滤掉无绑定材料（第 78–88 行）→ 这些材料**写进了仓库、随 APK 分发、但在数据库里不存在**。写作成本 100% 浪费，且**没有任何报错或计数**。
- **证据**：`[本轮实测]` 10356 材料 / 9464 绑定 ⇒ 892 条零绑定；`[审计记录]` 门指标 `unbound_materials = 892` 与之一致。
- **备注**：与 A-01 是同一问题的两面——材料总量够，但**没有落到需要它的节点上**。

### A-03 · 材料类型只有 2 种，缺 5 种（含自评优先级最高的那一种）【P1】
- **症状**：`CONCEPT_EXPLANATION` 6900 / `METHOD_MODEL` 3456；`MISCONCEPTION_GUIDE`、`WORKED_EXAMPLE`、`DERIVATION`、`REPRESENTATION_GUIDE`、`COMPLETE_SOLUTION` **各 0 条**。
- **失败路径**：`docs/kb-content-conformance-spec.md` §3.2 自评 `MISCONCEPTION_GUIDE` 为**选材优先级 0（最高）**、`WORKED_EXAMPLE` 为 1，但两者都是 0 条 → 最该有的类型一条没有。
- **证据**：`[本轮实测]` 计数；`[审计记录]` 门 `unbound_materials` 同一数据源。
- **缓解**：五三管线已产出 16 条 `MISCONCEPTION_GUIDE`（见 A-19），方向正确。
- **归属**：D-2 之后。

### A-04 · 每节点材料数分布倒置：649 个节点超配、998 个节点全空 【P1】
- **症状**：`0→998 / 1→344 / 2→245 / 3→185 / 4→152 / 5+→649`。
- **失败路径**：运行时 `TutorPlanInput.MAX_TEACHING_REFERENCES = 4`（`core/model/.../TutorTasks.kt:287`），`RoomTutorTeachingReferenceRepository` 按 role→type→title 排序后取前 4 条。**第 5 条起永远不可见**。所以 649 个超配节点里超出 4 条的部分是**死内容**，而同期 998 个节点一条都没有。
- **证据**：`[本轮实测]` 直方图 + `[本轮实测]` 源码常量；`[审计记录]` §5.3.4 登记了相关的预算饥饿路径（DAO 的 LIMIT 先于字符预算截断）。
- **含义**：这不是"材料不够"，是**生产没对准消费约束**。

### A-05 · 584 个名称不是知识点名 【P1】
- **症状**：`配方法：主要用于二次函数或可化为二次函数的函数，要特别注意自变量的取值范围．`（整句话当名称）；`偶次方根的被开方数的被开方数必须大于等于零，即中`（公式被剥离）。
- **失败路径**：这些名称进入 `KnowledgeSearchFeatureExtractor` 生成检索特征 → 名称噪声污染检索；同时作为学生端可见的"知识点"名字出现（掌握度页、错题标签）。
- **证据**：`[本轮实测]` 门输出 `bad_names = 584`，含 8 条样例。

### A-06 · 96 个名称含 ★ 难度星号 【P2】
- **症状**：`病毒★★★☆☆`、`实验：使用高倍显微镜观察几种细胞★★☆☆☆`。
- **失败路径**：星号是教辅的难度标注，被当作名称一部分抽入。既污染检索特征，也直接违反 `docs/kb-content-conformance-spec.md` §2.2「禁用形态：含 ★」。
- **证据**：`[本轮实测]` 门输出 `starred_names = 96`，含 8 条样例。

### A-07 · 118 个同名重复知识点需合并 【P1】
- **症状**：`二面角 x2`、`分类 x3`、`意义： x2`、`倾斜传送带 x2`（"xN" 为重复份数）。
- **失败路径**：同名节点各自持有材料与绑定 → 检索时同一概念被切成多个候选互相竞争 top-5 名额；学生在掌握度页看到两条同名条目。
- **证据**：`[本轮实测]` 门输出 `duplicate_names = 118`。
- **备注**：生成器干跑投影已含"并 108"的计划，说明合并清单已在 `node_actions_reviewed.csv` 里定稿一部分。

### A-08 · 847 条幽灵别名（与当前绑定脱节）【P2】
- **症状**：别名表里 847 条指向的节点已不存在或已改名。
- **失败路径**：别名是检索特征的主要来源之一（精排权重 7），幽灵别名会**把查询引向错误的节点**——这是"误召回"的一个直接来源。
- **证据**：`[本轮实测]` 门输出 `ghost_aliases = 847`。

### A-09 · 968 条 boundary 含第三方原文摘录（分发风险）【P0 · 合规】
- **症状**：`boundaryMarkdown` 里含从教辅/教材直接摘录的原文，而非独立重写的边界描述。
- **失败路径**：这些字段随 APK 分发给学生。项目自己的来源政策（`docs/knowledge-source-governance.md`）要求全部来源默认 `REVIEWED_SYNTHESIS_ONLY`——**不复制来源表达**。968 条是**政策与产物直接冲突**。
- **证据**：`[本轮实测]` 门输出 `boundary_excerpt = 968`；`[审计记录]` 同一指标。
- **修法已有**：`tools/kb_build/textfix.py` 的 `strip_boundary_excerpt` / `has_verbatim_excerpt` 已实现剥离，`test_kb_textfix.py` 有 19 条测试守着。

### A-10 · 589 条 boundary 只有定位串，没有真边界 【P1】
- **症状**：`定位：数学必修第一册 第三章·函数的概念与性质。（见知识清单/教材）`。
- **失败路径**：boundary 是**出题范围的硬锚**——讲题时告诉模型"这道题的知识边界在哪"。定位串提供不了这个信息，等于该节点没有边界约束。而 boundary 同时是检索特征来源（权重 1）。
- **证据**：`[本轮实测]` 门输出 `locator_boundary = 589`。
- **根因**：`boundary_map.csv` 不存在（A-16）。生成器投影里"2141 条 boundary 待定稿"是同一件事的全量。

### A-11 · 194 处 LaTeX 命令丢失反斜杠 【P1】
- **症状**：`\frac` 之类被抽成 `frac`，公式失去语义。
- **失败路径**：数学/物理内容直接进入模型提示词 → 模型读到损坏公式；学生在材料里看到损坏公式。
- **证据**：`[本轮实测]` 门输出 `latex_damage = 194`。
- **修法已有**：`tools/kb_build/textfix.py:180 repair_latex_commands`，`test_kb_textfix.py` 有一条测试遍历**全部真实 sidecar 材料**断言 0 残留。
- **已知代码缺陷**：`gate.py` 中 `_is_latex_damaged` 被**重复定义两次**（第 132 行与第 146 行），后者静默覆盖前者，第一套基于 `_REAL_LATEX_COMMANDS` 的实现是死代码 → **门用的判定函数不是作者以为的那一个**。

### A-12 · 80 条材料含控制字符 【P2】
- **症状**：材料正文出现 `\n\r\t` 之外的控制字符（历史上还有两条字面 NUL 字节，在 2026-09-09 审计中修过源码，但侧车数据仍有）。
- **失败路径**：导入契约 `KnowledgeTeachingMaterialContract` 会拒绝含控制字符的材料 → **这 80 条在导入时被拒**（与 A-02 的"静默丢弃"不同，这是契约拒绝）。
- **证据**：`[本轮实测]` 门输出 `control_chars = 80`。
- **修法已有**：`tools/kb_build/textfix.py:293 strip_control_junk`。

### A-13 · 2163 个节点的定位串与章节表不一致（占 84%）【P1】
- **症状**：节点定位写作 `数学必修第一册 函数的概念与性质`，章表是 `数学必修第一册 第三章 函数的概念与性质`——**缺章序号**。
- **失败路径**：定位串是内容可追溯性的载体（"这个知识点依据哪一章"）。84% 不一致意味着**追溯链在绝大多数节点上是断的**；同时它让"哪些章的节点还没材料"这类统计无法可靠计算。
- **证据**：`[本轮实测]` 门输出 `chapter_locator_mismatch = 2163`，样例为数学必修一第三章。
- **根因**：生成器 `_rebuild_topics` 会从章表**派生**定位串，但该重建尚未执行到成品包。

### A-14 · 6 处标记为跨章拆分却缺节点级覆盖 【P2】
- **症状**：物理"专题11 恒定电流"缺 `电流：`、`电动势：`；"专题12 磁场"缺 `定义：通电导线在磁场中受到的力叫安培力。`；"专题14 交变电流"缺 `电磁波：`；"专题17 热学"缺 2 条。
- **失败路径**：这些是拆分时**掉在地上的碎片**——原文被拆到别的节点去了，留下一个空的壳。
- **证据**：`[本轮实测]` 门输出 `chapter_split_missing_override = 6`，含逐条样例。

### A-15 · 1489 条前置边全部"未在权威表声明" 【P1 · 决定 D-3】
- **症状**：1489 条 `prerequisiteSlugs` 一条都没有对应的权威表条目。
- **失败路径**：门无法区分"这条前置是对的"和"这条前置是编的" → 1489 条边全部处于**不可信状态**。项目此前的处置是整体留空。
- **用户决定 D-3**：**不留空**。因此需要的是"未定"一等状态 + 逐条裁定通道，而不是删除。
- **证据**：`[本轮实测]` 门输出 `undeclared_prereq = 1489`；`[本轮实测]` 包内实测 prereqEdges = 1489。
- **外部对照**：`[外部研究]` cn-k12-math-knowledge-graph 对 596 个零入度主题的处理是 **438 个显式保留"未定"、拒绝写成"确认无前置"**，并公开 trace/release hash〔一手项目文档〕。这是可直接照抄的处置形态。

### A-16 · 两张权威表根本不存在 【P0 · 多数 A 类问题的根因】
- **症状**：`tools/kb_build/tables/boundary_map.csv` 与 `prereq_map.csv` **在磁盘上不存在**，但 `tools/kb_build/tables.py` 与 `build.py` 都引用它们。
- **失败路径**：`load_boundary_map` / `load_prereq_map` 读不到 → 所有 boundary 与前置都判"未声明" → 直接产生 A-10（589）、A-15（1489），并间接产生生成器投影里的"1571 条 boundary 剥离、2141 条待定稿"。
- **证据**：`[本轮实测]` `tables/` 目录清单（16 个文件，无这两个）；`[外部研究]` 无需。
- **含义**：**这不是内容质量问题，是定稿流程没走完**。补上这两张表是 A 类里杠杆最大的一步。

### A-17 · 节点是"空壳"：没有 definition / formula / examples 字段 【P1】
- **症状**：一个知识节点的全部内容是 `slug, name, aliases, kind, boundary, sourceLocator, prerequisiteSlugs`——**没有学科内容本身**。内容全部寄托在"材料"侧车的 4 个 markdown 字段上。
- **失败路径**：没有材料的那 998 个节点（A-01）就是彻底的空壳；有材料的节点也只有在材料被选中（≤4 条、≤20000 字符）时才"有内容"。
- **证据**：`[本轮实测]` 解析 `moe-2025-four-subjects-v1.json` 的键集（7 键）。
- **外部对照**：`[外部研究]` K12-KGraph 的 Concept 节点带 `definition / formula / aliases / examples`，边带 evidence 回指教材原文〔一手项目文档〕；Marble 的 micro-topic 带 `evidence`（掌握证据判据）与 `assessmentPrompt`〔一手项目文档〕。**本项目缺这两类字段**。

### A-18 · 材料—节点绑定正确率抽样仅 42% 【P0】
- **症状**：抽样核对显示只有 42% 的绑定"完全一致"，主要误绑发生在同章相邻概念（光合作用↔细胞呼吸、电场力做功↔弹力做功）。
- **失败路径**：绑定错误 = **讲错知识点**。学生做错一道题，系统认为他错在邻近概念，掌握度记到错误的 KC 上，后续排程与讲解全部偏。
- **证据**：`[技术文档]` `docs/kb-content-conformance-spec.md` §4.2 自述"现行抽样只有 42% 完全一致，必须做实"。
- **外部对照**：`[外部研究]` cn-k12-math 的做法是每条边带 stable ID + trace ID + source type + release hash〔一手项目文档〕。**本项目缺"可审计绑定"**。
- **备注**：这是全册里唯一直接影响**学习正确性**的内容问题，严重度不低于 A-01。

### A-19 · 五三管线已产出的材料尚未并入成品包 【P2 · 正常在途】

- **失败路径**：暂无——这是正常在途状态。记录它是为了后续统计时不要把"已写"当成"已生效"。
- **证据**：`[本轮实测]` 文件行数、逐行解析的类型分布。

### A-20 · 五三候选约一半未解析到既有节点 【P2】
- **症状**：`wusan_resolved.csv` 6538 行解析成功、`wusan_unresolved.csv` 6321 行未解析（设计上**刻意不做模糊匹配**）。
- **失败路径**：未见得是缺陷——未解析项一半可能是噪声（页眉、碎片），一半可能是**真缺的知识点**。未逐条裁定前不能当缺口，也不能当噪声。
- **证据**：`[本轮实测]` 行数；`[文件]` `tools/kb_build/resolve_points.py:144`。

### A-21 · 逐章补材料章节仍有 28.2% 的节点没材料 【P2】
- **症状**：`wusan_plan.csv` 95 章覆盖 2170 个节点，其中 1557 有材料 → 缺 613 个；95 章里 **75 章标"部分无材料"**、20 章标"有节点有材料"。

- **证据**：`[本轮实测]` 解析 `wusan_plan.csv`。

## B. 覆盖基线层（"全覆盖"的判定基础 · 12 条）

### B-01 · 外部不存在可核验的权威"高考考点总数" 【P0 · 决定 D-5】
- **症状**：无法用"一个权威数字"来闭合"全覆盖高考考点"这个验收标准。
- **证据**：`[外部研究]`
  - 国办发〔2019〕29 号原文：**"实施普通高中新课程的省份不再制定考试大纲"**〔官方〕
  - 教育部教育考试院高考栏目"考试大纲"分类页**最新条目 2019-01-31**〔官方站点〕
  - 《中国高考评价体系》配套答记者问原文：**"中国高考评价体系不是考试大纲，也不是界定考试范围的规范性文件"**〔官方〕
  - 学科网/菁优网/组卷网均不可访问（反爬），**未找到任何可核验的分科考点计数**〔未找到〕
- **归属**：D-5 → 结论见 `docs/research/coverage-baseline-design-2026-09-15.md`。

### B-02 · 课标 2025 提取是机械提取，全部 DRAFT_UNREVIEWED 【P1】
- **症状**：`knowledge-coverage-ledger-2025-v1.json` 九科 125 模块 / 1322 条候选知识点，**九科的 `mappingState` 全是 `DRAFT_UNREVIEWED`**；模块级 `requirementType` 分布 `REQUIRED 35 / SELECTIVE_REQUIRED 27 / ELECTIVE 63`。
- **失败路径**：这份清单**不能作为覆盖证据**——门 `audit-knowledge-coverage-ledger.ps1 -RequireComplete` 要求 `REVIEWED`，而 `REVIEWED` 又要求来源为 `ACQUIRED_REVIEWED`。

### D-01 · stage-1 排序无 IDF、无长度归一化 【P1 · 决定 D-4 降级为"靠后"】

### D-02 · 精排权重全部硬编码、无依据 【P2】
- **症状**：`名称×8 + 别名×7 + boundary×1 + 精确短语 80/70 + 父级×3`，全部为内联字面量。
- **失败路径**：违反项目自身的 `algorithm-parameters-science-grounded` 要求（算法参数须研究 + 交叉验证 + 标注证据等级）。改变任一权重只改分数、不改已知结论，**因为没有能分辨差异的数据集**（见 D-03）。
- **证据**：`[本轮实测]` `KnowledgeContextRetriever.kt:69-95`。

### D-03 · 检索基准只有 20 条手写题面，太小 【P1 · D-01 的前置】
- **症状**：`FourSubjectRetrievalBenchmarkTest` 用 `RetrievalBenchmark.queries` 的 **20 条**手写题面，`expected` 用"名称子串"近似，阈值 `Recall@5 ≥ 0.85 / crossSubject == 0 / MRR ≥ 0.7`。
- **失败路径**：IR 文献下限是 **50 条 query**，且 Voorhees 2009 证明即使 50 条"显著差异也可能错"〔A 级〕。当前 20 条足以做冒烟门，**不足以支撑任何参数裁决**。
- **证据**：`[本轮实测]` 我复跑该测试：**0 failures**，`Recall@5 = 0.95 (19/20)`、`Precision@5 = 0.70`、`MRR = 0.842`、跨科误召 0；`[外部研究]` Voorhees & Buckley 2002 / Voorhees 2009 / Sakai 2015〔A 级〕。
- **含义**：D-01 的施工顺序应是**先扩基准到 ≥50 条并切分调参集/报告集，再改评分**。

### D-04 · 逐章题面 Recall@5 只有 0.733，且刻意不进阈值 【P1】
- **症状**：新增的 `chapterQueries`（15 条，覆盖正在逐章补材料的章节，预期节点全部取自这些章里**已绑定材料**的节点）在暂存包上 `Recall@5 = 0.733 (11/15)`、`Precision@5 = 0.253`、`MRR = 0.70`。它**不参与** `FourSubjectRetrievalBenchmarkTest` 的阈值断言。
- **失败路径**：这是"材料 → 标题 → 别名 → 召回"这条链的**唯一可见水位**，也是五三内容投入能否转成检索收益的唯一凭证。0.733 说明这条链目前是漏的。
- **证据**：`[本轮实测]` 我复跑出的指标（`build/benchmark-metrics.txt` 写入了两套数字）。
- **备注**：作者在注释里说明"口径保持不变，要不要并进门槛是将来的单独决定"——**这个决定现在到了**。`[外部研究]` 支持先把金标集切分调参/报告集再谈门槛〔Anserini 官方方法 B 级 + Voorhees 2009 A 级〕。

### D-05 · Python 检索质量门是脚手架，不能作为门 【P2】

- **证据**：`[本轮实测]` 金标集内容、`evaluate` 源码、grep 无调用点。

### D-06 · `KnowledgeRetriever` / `KnowledgeRetrievalBenchmark` 是死代码 【P3】

### I-05 · 绑定正确率**无法**用字符串度量（订正 A-18 的可用口径）【P1】
- **症状**：我先后用两个词面口径测量 9464 条绑定，得到两个互相矛盾的数：
  - **宽松口径**（二元组重合）：98.1% 命中 —— **虚高**。`下丘脑…胰岛 A 细胞` 里的"细胞"与节点名 `光合作用与细胞呼吸…` 里的"细胞"对上了，通用词污染。
  - **严格口径**（标题/节点名互为子串）：16.4% 命中 —— **虚低**。`离子方程式正误判断之一看：是否符合客观事实` → `离子方程式的正误判断方法` 是**正确**绑定，只是标题用了"之一看"的面相写法，不含节点名。
- **失败路径**：材料标题是**面相式**写法（`之一看：…`、`曲线先降后升→…`），刻意不重复节点名——这是好的内容写法，但它使**词面匹配既不能验证也不能生成正确绑定**。任何用字符串规则做的绑定门都会给出无效数字。
- **证据**：`[本轮实测]` 两个口径各自的全量结果与反例（各 3 条，打印在测试输出里）。
- **含义**：**Phase 5 的绑定门必须是语义判定**（模型判定 + 人工抽样复核），不能是正则或子串检查。规范 §4.2 里那个"42% 完全一致"来自人工抽样，正则复现不了它，也不该试图复现。

## M. 别名上限与 topic 顺序轮（2026-09-19 · 三处缺陷）

起因是两处内容缺陷（25 个节点别名 >32、4 个 topic 排在父级之前）。逐条查证后，
**它们都不是内容缺陷，而是代码/工具的缺陷**——内容只是被拒被藏；同时查出一个此前没登记的 P0。

### M-01 · `MAX_ALIASES = 32` 让 25 个知识点进不了任何用户的库 【P0 · 已修】

**症状.** `KnowledgeBaseImportContract.validateAliases` 有一条 `require(aliases.size <= 32)`。
实测成品有 **25 个节点**越线（BIOLOGY 23 / MATH 1 / PHYSICS 1，最多的是生物「基因工程」84 条），
于是它们在调和时被逐条跳过（`problemWith` → `skipped`），**只在 `content_install_state` 里留一行**，
学生永远看不到这 25 个知识点。

**它为什么是缺陷而不是安全边界.** 这条上限**没有依据**：无 KDoc、无具名常量、不从任何预算推导。
真正的预算是 `KnowledgeSearchFeatureExtractor` 的 **16 个片段 / 192 个特征**，而它**与别名条数无关**——
84 条别名与 39 条别名都只产出 16 个片段。全仓检索确认：没有测试、文档、门或审计脚本依赖 32。

**修复.** 删除该上限（保留逐条约束：每条 ≤200 字、去空白、大小写不敏感唯一）。
**这不是"修别名膨胀"**——不削减任何别名，只是不再因为条数把整条节点拒掉。

**证据（红/绿都跑了）.** 新增 `BundledKnowledgeNodesContractTest`：用调和器判跳的同一个函数
`KnowledgeBaseImportContract.problemWith`、同一份 `byId`，逐条过内置包的全部节点，要求零拒绝。
把上限临时加回去 → **FAILED**，报出的正是这 25 个节点（`math:三角形面积公式`、`biology:细胞学说`…）；
删掉 → 绿。

### M-02 · `KnowledgeBaseNodeContext.MAX_ALIASES = 8` 静默藏起 538 个节点 【P0 · 已修】

**这一条是本轮新发现的，此前没有登记。** 与 M-01 是同一类错误的另一个出口：

`KnowledgeBaseNodeContext` 有 `require(aliases.size <= 8)`，而适配函数
`toKnowledgeBaseContext` 用 `runCatching{…}.getOrNull()` 包着它、调用处再 `mapNotNull` ——
**9 条以上别名的节点静默变成 null**，从"整理模型"的候选菜单里消失，**无日志、无计数**。实测 **538 个节点**受影响。

**方向最坏**：能进候选菜单说明它本来最相关，而**被藏起来的恰恰是材料最多的那些节点**
（`基因工程` 86 条材料 → 84 条别名 → 永远到不了模型）。

**修复.** 构造前把别名**确定性截断**（`sorted().take(8)`）而不是让构造失败；类型上的 `require` 保持不变
（模型类型的不变量应当严格，"把内容适配到不变量"是数据层的责任）。残余的其它丢弃原因
（如主名超 96 字）现在**记账并记一行日志**（截断数 + 丢弃数），不再无声。

**为什么是截断不是抬高上限.** 这个上下文最多带 64 个节点进提示词；上限存在的意义是
**提示词有界**，截断保住了这个意义，同时把"节点消失"换成"别名变少"——后者无害（主名是独立字段，永远在）。

### M-03 · 4 个 topic 排在父级之前（会让安装撞外键） 【已修 · 成品已重排】

**症状.** `topics` 是平铺数组、按顺序逐个变成节点，而 `knowledge_node.parent_knowledge_node_id`
是自引用外键、逐行检查 → 子级排在父级前面就 `FOREIGN KEY constraint failed`。
成品里有 4 处（如 `MATH·综合` 排在 `MATH` 之前）。成因是 `relocate_points.py` 的
`ensure_synthesis_chain` 无条件把新建的「综合」链 `append` 到数组尾。

**诚实说清价值**：生产安装路径已被调和器的 `parentFirstOrder` 容忍，所以这次修的是
**成品自身的正确性 + 防复发 + 关掉一个顺序盲的公开端口**（`importKnowledgeBase` 校验用 map、
写入用数组顺序），**不是解锁任何生产功能**。

**处置.** 新增 `topic_order.parent_first`（纯函数、稳定、父级先序）与 `order_topics.py`（报告 / `--write` +

成品重排 4 → 0（458 行增删，**已验证是纯置换**：删除集与新增集作为多重集相等）。

**本轮验证.** 门：只有 `topic_parent_after_child` 一项变化（**4 → 0**），其余 18 项与 HEAD 逐字相同
（用 HEAD 的包在临时目录重跑门做的对比）；未通过项 11/19 → 10/19；`roundtrip` 7/7 OK。

**未做（用户裁定）**：不削减别名（别名膨胀是过度绑定的症状，已登记）、不减材料绑定
（1019 个节点绑 >4 条材料）、不把排序放进解码器。

**顺带更正一条 overstated 的说法**：`roundtrip.py` 的结论文案写的是"生成器可忠实重放现行成品"，
但它**不运行生成器**——它是"读文件 → 重新序列化 → 与磁盘比对"，证明的是**序列化器保真**。
不影响本轮结论，登记为观察。
