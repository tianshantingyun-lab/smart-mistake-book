# 智能错题本仓库威胁模型

## Overview

本仓库实现面向高中生的 Android 智能错题本。核心数据包括学生拍摄的题图、手写内容、结构化题目文档、错题与复习记录、掌握度证据、Provider 配置和 API 凭据。产品以大模型能力为主，但大模型、Provider 返回值和外部接收应用都不属于可信计算基。

当前安全目标不是制造一个功能残缺的“离线模式”，而是保证：本地状态和用户事实由应用控制；每次外发都具有精确、可解释、可撤销到重新确认的授权边界；模型只能提出候选结果，不能直接改写学习事实、错题记录或本地文件。

## Threat Model, Trust Boundaries, and Assumptions

### 受保护资产

- 原始题图及其中可能出现的姓名、学校、班级、笔迹、作答痕迹和其他未成年人信息。
- 题图经过方向校正、元数据剥离后形成的 canonical 私有资产，以及其 SHA-256、尺寸和字节数。
- 结构化题目文档、学生确认过的题干/公式/选项/图形证据和错题库记录。
- 学习事件账本、知识点掌握状态、复习计划、讲题会话和学生选择。
- Provider、模型、Base URL、能力快照、提示词策略版本和 API Key。
- PDF/图片转文档导出物、系统分享授权和临时 FileProvider URI。

### 信任边界

1. **相机/系统 Photo Picker → 应用私有资产库**：外部 URI 和图片字节不可信。导入必须限制大小、尺寸、像素预算和格式，修正方向、移除 EXIF，并写入内容寻址的私有文件。
2. **Compose UI → 领域命令 → Room 事务**：UI 状态不是事实。错题入库、讲题结束、复习作答和掌握度更新必须通过领域校验及幂等/CAS 事务。
3. **本地应用 → 外部 Provider**：这是最高风险的数据出站边界。外部 Provider 只有在任务持有与当前题图、Provider、模型、配置版本和提示词策略完全一致的单次授权清单时，才能获得受限字节流。
4. **Provider 输出 → 结构化解析/策略层**：模型输出始终是不可信输入。Markdown、公式、动作 ID、数组、嵌套深度、字节数和状态转移必须受强类型合同和预算约束。
5. **模型候选 → 用户事实/学习记忆**：模型可提出分类、题目结构、讲解步骤或复习建议，但不得直接提交错题、宣布掌握、删除历史或写学习账本；需要学生确认或确定性的本地策略。
6. **应用 → 系统分享/打印/其他应用**：导出物只通过私有、短时、最小权限 URI 暴露；接收应用和打印服务不可信。
7. **开发/测试工具 → 工作区与设备**：SDK、Gradle、ADB、模拟器、缓存、日志和临时文件应留在 `D:\智能错题本` 的工作区边界；用户配置目录残留视为失败并立即收敛回工作区。
8. **错题库 ↔ 掌握库的本地中继**：两个物理数据库彼此不共享事务，也不把“能读到一行消息”当作来源证明。接收方只接纳由来源库所有者在可信入队时签发、持久保存并完整绑定学生、方向、数据库代次、聚合版本、幂等键、载荷指纹和事件指纹的消息；验签、来源代次钉扎、验证回执与业务写入必须在接收方同一所有者事务内完成。

### 安全不变量

- Model Gateway 不能自行读取 Room、任意文件路径、任意 URI 或 API Key；图片只能从 `RestrictedModelAssetSource` 按已授权资产 ID 获取。
- 外部执行必须携带持久化的 `ModelEgressManifest`，且授权对象只能由 `ModelEgressPolicy` 构造。
- 授权精确绑定 subject、任务种类、Provider、模型、Provider 配置版本、提示词策略版本、资产 ID、SHA-256、字节数、尺寸和可选区域。
- 题图授权仅覆盖 `CAPTURE_ASSESS` 与 `CAPTURE_PARSE`；明确禁止其他题图、完整学习历史、API 凭据和拍摄元数据。
- Provider/模型/配置或题图发生变化时，旧授权失效并要求学生重新确认。
- 外发授权只在批准后 15 分钟内有效，拒绝超过 2 分钟的未来时间；提示词策略必须是当前版本。Gateway 在真正发起 HTTP 前再次读取能力与配置，并用原始 External manifest 重新执行完整策略授权；Local permit、过期许可或失配清单都不能在网关内升级为网络许可。
- 区域授权在存在可信裁切字节流之前失败关闭，不能以“整图代替区域”发送。
- API Key 不进入模型输入、数据库普通字段、日志、分享/导出或 Android 备份；网络认证与模型业务载荷分离。
- 模型输出不能直接成为已确认文档、错题或掌握度事实；验证、显式确认和可审计状态转换不可绕过。
- 学习模型、Provider 响应和题面都不能请求反射、动态类加载、任意方法调用、原始中继、DAO 或 SQL；跨库写入只有固定的本地所有者操作，模型只能提交证据引用完整的候选。
- 跨库消息不得在读取时补签。未签名历史消息永久标记为旧来源并退出授权链；恢复当前题目与知识绑定只能由来源库按当前事实重新签发，历史复习回答不得被追溯“认证”。
- 图片转文档保留来源证据；无法可靠重建的图形不静默猜测，原图与草稿继续保留。仍可继续时不打断，只有任务确实无法继续才询问最小缺失信息；手动修订只能由学生主动进入，不是默认退路。

### 假设与范围

- Android 沙箱、系统 Photo Picker、Keystore 和受支持设备的文件权限按平台合同工作。
- 正常设备上的同一 UID 代码被视为应用信任域；root、恶意系统镜像、内核级攻击和物理芯片提取不在当前版本可完全防御的范围内。
- 已签名 APK 中的应用代码与打包依赖属于可信计算基。Java/Kotlin 可见性和 package-private 只用于收窄正常源码误用面，不能阻止任意恶意同 UID 代码、反射、手写字节码或被篡改的供应链依赖；因此最终门槛还必须包含依赖审计、编译后 API 扫描与功能攻击测试，不能把访问修饰符本身描述为安全沙箱。
- 用户选择的 Provider 可能保留请求、遭入侵、返回恶意内容或与声明能力不一致，因此仍按不可信外部系统处理。
- 当前仓库已接入 OpenAI-compatible `/chat/completions` 多模态适配器和真实题图读取主链；但没有仓库内置 Key，也尚未用用户指定的真实 Provider 完成线上评测，因此不能把协议接通等同于识别质量已经验收。

## Attack Surface, Mitigations, and Attacker Stories

| 攻击面 / 攻击者故事 | 影响 | 当前或要求的缓解措施 | 剩余风险 |
|---|---|---|---|
| 恶意图片利用解码器、超大像素或压缩炸弹耗尽内存 | 崩溃、ANR、拒绝服务 | 导入前后限制字节/尺寸/像素预算；只保留规范化私有副本；重新校验哈希与尺寸 | 平台解码器漏洞仍依赖系统更新 |
| 题图含姓名、学校或定位 EXIF，被无感发给 Provider | 未成年人隐私泄露 | canonical 化时剥离元数据；发送前说明接收方、数据和目的；授权清单明确禁止拍摄元数据 | 图像像素内的身份文字仍可能存在，需要后续可见预览/遮盖能力 |
| UI 批准 A 图后，竞态或引用替换令 Provider 读取 B 图 | 越权外发 | 授权绑定 ID/hash/bytes/dimensions；读取时重新查 Room 与 vault 并复核；Provider 只能拿受限流 | 文件系统被 root 篡改不在完整防御范围 |
| Provider 设置改变后复用旧同意 | 数据被发送给未批准接收方 | Provider、模型和配置版本任一变化都令策略拒绝旧授权 | 配置版本生成必须覆盖 Base URL、模型和相关数据策略字段 |
| 适配器绕过策略层自行构造执行凭证 | 任意题图外发 | `ModelGatewayExecution` 构造器为模块内受限普通类；Repository 统一授权；源读取再次比对持久化清单 | 未来模块拆分若扩大 `internal` 边界需重新审计 |
| 仅批准裁切区域却发送整张图 | 过度收集 | 当前区域 grant 一律失败关闭，直到实现可验证的裁切流 | 暂时牺牲区域发送功能 |
| Prompt injection 诱导模型索取 API Key、其他错题或完整历史 | 凭据/隐私泄露 | 模型没有文件、Room 或密钥读取能力；禁止数据类别在合同中显式声明；工具调用采用白名单动作 ID | Provider 仍可在自然语言中诱导学生手工泄露，需要 UI 提示与内容策略 |
| 恶意模型输出超长 Markdown、深层 JSON、非法动作或伪造“已掌握” | 崩溃、状态污染、错误教学 | 输出预算、强类型解析、Markdown/公式安全渲染、状态机校验；掌握度只由本地学习证据投影 | 教学内容的事实错误需要引用/复核与用户反馈机制 |
| 恶意或错误的多题边界制造极小、重叠、越界裁切，或在中途失败后留下半套草稿 | 丢题、内存耗尽、待处理状态污染 | 只接受 2–12 个有限坐标；限制最小宽高/面积与最大重叠；从已校验私有原图本地裁切；全部子草稿在一个 Room 事务中创建，失败清理未引用裁图并保留原草稿；稳定 ID 支持精确重放 | 模型仍可能给出形式合法但语义错误的边界，真实 Provider 需要多学科样本评测 |
| 共享设备上的其他用户打开应用查看错题和学习数据 | 隐私泄露 | Android 用户隔离与应用私有存储；后续可选应用锁/隐藏预览 | 当前没有独立账号/应用锁时，同一系统用户仍可访问已解锁应用 |
| 恶意接收应用长期持有 PDF/题图 URI | 导出数据泄露 | FileProvider `exported=false`，只授予目标动作所需的临时读取权限；不暴露真实路径 | 接收方读取后的副本无法由本应用撤回 |
| Base URL 指向明文 HTTP、回环/内网或伪造兼容服务 | 凭据窃取、SSRF/内网探测 | 设置层要求 HTTPS；请求前解析并拒绝回环、局域网、链路本地、CGNAT、组播和保留地址；单次客户端固定本次 DNS 结果、禁用系统代理、自动重定向和自动重试，并设置请求/响应与连接时限 | DNS 首次解析和公共 Provider 本身仍不可信；私有部署/自签名需单独设计显式高风险流程 |
| Provider 返回伪造题块 ID、其他图片 ID、已确认状态或预选答案 | 越权引用、错误答案或未经确认的记录入库 | 适配层只接受受限 wire DTO；文档/题块/选项 ID、本次来源资产、provenance、reviewStatus 和 producerVersion 均由本地重建；`selectedChoiceId` 固定为空；Repository 再执行完成态合同校验 | 模型仍可能转写错误；原图证据与随时修订入口必须保留，但正常候选不得要求学生逐块确认 |
| 日志、崩溃报告或备份包含 Key/题图/完整模型输入 | 二次泄露 | 密钥使用 Keystore 封装；敏感值不写日志；备份规则排除私有凭据和临时导出 | 第三方 SDK 接入前必须逐项审计采集范围 |
| 重试、进程恢复或并发执行导致同一题图被重复发送 | 费用增加、隐私放大、状态冲突 | 请求指纹、持久任务、幂等/CAS、并发输家跟随赢家；重试需显示且受配额约束 | Provider 未提供幂等键时仍可能处理已到达但响应丢失的请求 |
| 依赖、构建工具或测试脚本被篡改 | 恶意代码进入 APK、密钥/数据泄露 | 固定工具摘要、受保护 ACL、工作区专用缓存与 ADB 端口；升级后重新审查摘要；构建不使用 hook 绕过 | 第三方依赖供应链仍需版本锁定、SBOM 和持续扫描 |
| 冷启动/JIT 退化导致学生误以为应用或 AI 卡死 | 可用性损害、反复点击造成重复操作 | 启动路径基准、明确的本地加载状态、关键按钮幂等；不得用虚假的“模型思考”掩盖系统卡顿 | 当前已在 API 36 模拟器观察到一次启动 ANR，尚待专项修复 |
| 讲题模型借“个性化”读取完整学习史或其他题目 | 未成年人学习画像过度披露 | `TUTORING` 清单只允许 `CONFIRMED_QUESTION_DOCUMENT` 与命中当前题显式关联 knowledge node ID 的 `RELEVANT_LEARNING_EVIDENCE`，资产列表必须为空；没有显式关联时跨题证据发送空集合，本题精确记忆走独立有界字段 | 显式关系仍依赖题目整理质量，真实 Provider 上仍需最小披露审计 |
| 模型伪造“根据你的历史”或写入错误掌握结论 | 学习画像污染、后续追问和复习失真 | 输出只能引用本轮披露的显示标签；本地重建会话、题面和当前题内场景身份；模型知识点 ID 被拒绝；当前题白名单交互不能直接写掌握投影 | 模型教学事实仍需答案校验/评测，当前真实 Provider 质量未验收 |
| 题面内提示注入要求忽略讲题约束或泄露数据 | 越权输出、诱导学生、过度披露 | 系统提示明确题面是不可信内容；Gateway 无 Room/文件/凭据读取能力；输出是固定 JSON 且受长度、选择数、标签子集和主动内容检查 | 自然语言社会工程仍需举报与内容策略 |
| 伪造错题库中继行，或利用读取时补签把伪造行变成“可信消息” | 凭空制造错题事实、错误知识归因或污染掌握投影 | 来源所有者只在可信入队事务中签名并持久保存证明；读取路径不能签名；接收所有者原子执行验签、代次钉扎、回执和写入；坏 HMAC、缺证明或证明不匹配时数据库零变化 | 若已签名 APK 的可信代码或依赖本身恶意，同 UID 内仍可绕过；由供应链与发布完整性控制 |
| 替换整份来源数据库、回滚来源代次或重放旧未签名中继 | 旧数据重新取得当前授权、重复记账、跨安装混入 | 每次安装使用随机密钥身份和随机 Keystore alias；带密钥哨兵绑定来源数据库代次与中继 epoch；接收方首次原子钉扎来源代次，之后不同代次失败关闭；旧未签名收件和其派生链只保留审计、不得参与当前投影 | Android 系统整应用备份/恢复及清除数据后的产品行为仍需设备级专项验证 |

## Severity Calibration (Critical, High, Medium, Low)

- **Critical**：可在无学生批准的情况下批量外发 API Key、完整学习历史或多张未成年人题图；或远程执行代码并控制应用信任域。
- **High**：单次越权发送一张含敏感身份信息的题图；Provider 配置替换仍复用旧授权；模型输出可直接篡改学习账本、错题事实或删除数据。
- **Medium**：恶意输入稳定导致崩溃/ANR；短时 URI 权限范围过大；日志暴露非凭据但可识别的题目/学习记录；重试造成有限重复发送和费用。
- **Low**：不含敏感内容的错误提示、非持久 UI 状态混乱、无法跨越信任边界的轻微信息泄露或只影响开发环境的可恢复问题。
