# 正式高中知识包治理流程

本模块只管理 `high-school-knowledge.db`。候选资料、人工审核记录和签名材料属于离线构建产物，不写入运行时数据库；学生错题、聊天和掌握情况也不得进入本模块。

## 三阶段发布

1. 候选阶段
   - 生成完整知识包内容指纹和覆盖证明 v2。
   - 覆盖证明逐科绑定审核清单中预期的模块稳定编号和知识点稳定编号，并绑定关系、方法、例子结构和教材映射的精确摘要；缺项和单点占位范围都不能发布。
   - 为每个来源记录内容指纹、版本、出版社、固定地址、许可表达式、许可证据及其指纹。
   - 为九科分别记录课标来源、根知识点稳定编号命名空间和至少一个教材版本映射。
   - 根据知识包真实内容计算覆盖指纹，不能手填数量冒充覆盖。
2. 独立复核阶段
   - 复核单位必须与制作单位不同。
   - 复核记录同时绑定候选治理指纹、完整内容指纹和实际覆盖指纹。
   - 必须确认包内只有原创或经审核的知识讲解、方法和例子结构，不含第三方题库。
3. 签名激活阶段
   - 签名绑定知识包、知识体系、搜索索引、候选记录、独立复核记录和激活代次。
   - 只接受源码中固定信任的 RSA-2048 以上公钥；运行时没有私钥和“临时信任”入口。
   - 私钥只能由离线命令从仓库外路径读取，口令只能来自环境变量。签名回执和生成源码只含公钥、签名与摘要。
   - 空公钥表、未知密钥、有效期外签名、撤销密钥、内容或证明摘要不一致都会失败关闭。
   - checked-in release 注册表和 release 公钥表当前都为空，因此正式版本保持关闭。

debug 中的一科一个根节点夹具只验证安装、数据库打开、篡改检测和代次边界。它有独立的 `DEBUG_BOUNDARY_FIXTURE` 身份，必须使用 `debug.` 命名空间，必须保持 `productionCutoverEligible=false`，不能带正式签名证明，不能被生产 runtime 打开，也不会进入 release。

## 激活前固定检查

- 正式内容制作输入和人工检索/归因验收留出集必须由不同流程登记；正式内容编译器只接收留出条目的带密钥 HMAC 指纹和签名清单，不能接收、保存或重建留出图片、题面、批注。
- 五项正式编译输入必须有独立的版本化输入清单；清单绑定实际输入产物与文本、规范化文本、派生文本、声明摘要和结构化值的集合摘要。
- 留出清单必须非空、经过独立 RSA 密钥签名且公钥仍有效、未撤销；发布登记的完整指纹必须预先钉在编译器中，并精确绑定签名公钥、HMAC 密钥承诺、清单指纹和发布代次。调用者自带公钥表、旧代次或同名换钥都不能获得信任。
- 任一留出图片摘要、提示、规范化或派生文本、批注、稳定验收编号或派生别名进入正式内容输入时，编译立即拒绝。扫描同时覆盖完整值、嵌入值、同一结构内拆分值、跨字段且夹有普通字段值的保序分片、带边界和类型域的短整数/小数/符号、JSON 化批注以及带前缀的图片摘要；规则不识别题号，也没有针对某道题或某个测试样本的例外。
- 正式输入、内容清单、留出清单和发布登记会在深拷贝、HMAC、签名验证及窗口扫描前完成严格 schema 检查，并受深度、节点数、UTF-8 字节数、字符串数、单字符串和窗口运算预算约束；循环、非 JSON 值、非有限数或超限输入一律失败关闭。
- 写入正式产物的合规报告只含清单编号、版本、整体指纹、各扫描面数量、留出条目数和零重叠结论，不含逐条指纹或任何真实留出内容。
- 九科都有独立的课标和教材版本映射。
- 每科都有主题层级、细知识点、知识关系、方法模型和例子结构。
- 知识点及讲解材料使用经过审核、与版本无关的稳定编号命名空间。
- 同科规范名称、展示名称和别名归一化后不能指向不同知识点。
- 每一个来源都与包内的标题、出版社、版本、地址、内容指纹和许可证据完全一致。
- 只允许参考的来源只能用于审核后的重新表述；摘录或改编必须具有明确自动使用许可。
- 例子结构默认要求原创或审核后的重新表述，不能把第三方原题及答案批量保存成题库。
- 制作、复核和签名时间顺序正确，复核单位独立，签名公钥在有效期内。
- 独立复核记录必须同时给出正式产物、运行时内容和覆盖证明的精确指纹；签名工具不会自行替复核者推断或补填。
- 任一映射、许可、覆盖、复核或签名不一致都拒绝激活。

## 离线生成与安装

正式内容完成人工审核后，先用 `compile-formal-knowledge-pack.py` 生成 schema v2 产物，再准备独立的 release governance JSON。正式编译必须同时提供正式内容输入清单、私有留出指纹清单、内容寻址的留出发布登记和仓库外 HMAC 密钥。发布登记只有其完整指纹已经进入编译器固定允许表时才可信；当前正式允许表为空，因此不存在可被命令行参数临时加入的信任根。HMAC 密钥可以显式传入，也可通过 `SMART_MISTAKEBOOK_HOLDOUT_FINGERPRINT_KEY_PATH` 指定；命令不会输出密钥、逐条留出指纹或真实留出内容：

```powershell
$env:PYTHONPATH = '.\tools'
$env:SMART_MISTAKEBOOK_HOLDOUT_FINGERPRINT_KEY_PATH = '<仓库外的HMAC密钥路径>'
python .\tools\compile-formal-knowledge-pack.py `
  --check `
  --content-input-manifest '<正式内容输入清单.json>' `
  --holdout-manifest '<私有签名留出指纹清单.json>' `
  --holdout-release-registration '<已钉住指纹的留出发布登记.json>'
```

`--write` 使用同一组必选治理输入生成正式产物；`--status` 在缺少其中任何一项时只报告阻断，不会推断或补造证明。真实留出图片、题面和人工标注由独立验收系统保管，不进入仓库、正式内容目录或合规回执。

release governance 文件必须包含逐来源许可证据、九科课标/教材映射、独立复核绑定的三个精确指纹以及签名时间窗；工具不会自动产生这些事实。离线签名前还必须提供独立管理的正式签名登记。该登记的完整内容指纹和代次必须预先钉住，并精确绑定 `keyId`、RSA 公钥指纹、有效期和发布代次；新生成的 registry、本次命令行参数或调用者私钥都不能自行成为信任根。当前正式签名登记允许表同样为空。

私钥必须存放在仓库之外。可显式传路径，也可通过
`SMART_MISTAKEBOOK_KNOWLEDGE_SIGNING_KEY_PATH` 传入；加密 PEM 的口令只通过
`SMART_MISTAKEBOOK_KNOWLEDGE_SIGNING_KEY_PASSWORD` 传入：

```powershell
$env:PYTHONPATH = '.\tools'
$env:SMART_MISTAKEBOOK_KNOWLEDGE_SIGNING_KEY_PATH = '<仓库外的私钥路径>'
$env:SMART_MISTAKEBOOK_KNOWLEDGE_SIGNING_KEY_PASSWORD = '<仅当前进程可见的口令>'
python .\tools\generate-formal-knowledge-release.py `
  --formal-pack '<schema-v2-formal-pack.json>' `
  --governance '<independently-reviewed-release-governance.json>' `
  --formal-build-inputs '<五项正式编译输入.json>' `
  --content-input-manifest '<正式内容输入清单.json>' `
  --holdout-manifest '<私有签名留出指纹清单.json>' `
  --holdout-release-registration '<已钉住指纹的留出发布登记.json>' `
  --release-signing-registration '<已钉住指纹的正式签名登记.json>' `
  --output-directory '<release Kotlin 生成目录>' `
  --receipt '<公开签名回执.json>'
```

命令确定性生成两个 Kotlin 文件：

- `GeneratedFormalKnowledgePackAsset.kt`：把审核产物精确转换为
  `ReviewedKnowledgePack` 和形式化证明对象。
- `GeneratedFormalKnowledgePackRegistry.kt`：只保存公开密钥、签名、摘要以及对审核资产的固定引用。

签名前会先核对正式签名登记，再使用原始五项输入重新执行完整隔离门禁，并要求重新得到的合规报告与正式产物逐字段一致；只有私钥导出的公钥与已钉住登记完全相同才允许签名。两个正式 Kotlin 渲染器只接受安全签名流程内部签发、绑定精确输入且每项只能消费一次的授权；公开函数或直接 import 传入普通字典、调用者公钥都不能生成可激活产物。生成器随后重新核对固定登记、签名回执、签名载荷和两个源文件哈希，CLI 写盘后再次读取并核对文件哈希。发布入口不接受新生成 registry 自带的公钥作为信任依据，也不接受产物自报的“零重叠”结论。

运行时继续由 `TrustedLocalKnowledgePackProvisioning.toInstallBundle` 从
`ReviewedKnowledgePack` 确定性重建搜索行和 Room 安装资产，然后再次计算 Room 内容指纹。生成器不写 SQL、不接受模型脚本，也没有运行时注册表修改入口。

## 仍需人工完成的正式语料工作

当前代码只提供治理机制，没有伪造任何已审核知识点。正式 release 仍缺少：

1. 九科国家课标正文的逐科人工范围拆分、稳定编号方案和可核验来源记录。
2. 各科需要支持的主流教材出版社、册次和版本清单，以及每个版本的人工核对证据。
3. 第三方教培资料的逐来源许可审查；仅有网页可访问或模型声称“可用”不能通过。
4. 全高中细知识点、别名、前置/相关关系、方法模型和例子结构的人工制作与双人复核。
5. 各版本教材章节到共同知识点的映射，以及跨版本冲突处理记录。
6. 对旧版稳定编号的连续性审计；删除、合并、拆分知识点时必须提供迁移清单。
7. 与制作方不同的复核组织、正式复核记录和离线保管的发布私钥。
8. 九科检索标注集、覆盖审计结果和回归结果；这些结果通过后才可把签名包加入 release 注册表。

在上述工作完成前，release 注册表保持空是正确状态，不应使用 debug 夹具、模型生成内容或测试数据替代。
